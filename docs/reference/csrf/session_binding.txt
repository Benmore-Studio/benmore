A token from GET /api/_csrf sent with a session cookie (or Bearer session) is bound to that session and refused on any other. Every other token is unbound and validates on any session: the auto-injected meta tag and form fields (minted at page render, also for signed-in pages), and /api/_csrf fetched without a session. bm.auth.signIn keeps the page's pre-login meta token, so a single-page sign-in goes on using it; refusing unbound tokens for signed-in sessions would break every such page until it reloads. A cross-site forgery is stopped by the origin gate - Origin must equal the request host; without Origin, Sec-Fetch-Site cross-site/same-site is refused, so a sibling subdomain is refused too - and by the SameSite=Lax session cookie (`__Host-` over HTTPS), not by the token. A request that carries neither Origin nor Sec-Fetch-Site (a very old browser, a native client holding the cookie) is checked by the token alone, and anyone can fetch an unbound one; native clients should use Bearer auth, which needs no token.
