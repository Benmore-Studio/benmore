A Bearer-only request needs no CSRF token. Bearer-only means `Authorization: Bearer <token>` (a session token from POST /api/_auth/token, or a `bmr_`/`bma_` API token) and NO session cookie (`__Host-benmore_session`, or `_benmore_session` over plain HTTP). It covers the app's API writes: auto-CRUD (create, update, delete, batch, ingest, restore, /api/_transaction), /api/_scheduled (POST, DELETE), /api/_approvals (POST and /{id}/decide), /api/_query/views (POST, DELETE), notifications, locks, permissions, versions, workflow transitions, webhooks, uploads, roles, custom fields, API tokens, sessions, profile (PATCH /api/_auth/profile), act-as, logout and import. A request that carries the session cookie always needs the token, whatever Authorization header rides along (junk or another account's valid token): identity comes from the cookie, so the header cannot buy the exemption. Browser-only form endpoints never take it and always check the token (several also refuse anything but a direct browser sign-in): /login, /signup, /forgot-password, the verify-email and email-change confirmation forms, /settings/password, /settings/profile, /settings/delete-account, passkey endpoints, /_admin form posts (tools/run, set-role), managing connected AI clients and connection credentials, and the CLI device approval page.
