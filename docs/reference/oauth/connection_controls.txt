OAuthConnect discovers GET /api/_auth/oauth-providers (authenticated array of {provider, token_storage}) and lists stored connections via GET /api/_auth/oauth-tokens. BYO providers with both credentials use /auth/<provider>; managed providers are sign-in only and do not expose provider API tokens to the app. The component defaults to configured providers plus existing stored connections; an explicit providers option filters/orders the controls and marks unavailable entries as not configured. Loading failures are visible and retryable. DELETE /api/_auth/oauth-tokens/<provider> removes only the caller's stored token, not the provider's remote grant or the app session. Connection uses the existing OAuth sign-in flow: the verified provider email selects the app account; this is not arbitrary cross-email account linking. A stored connection keeps the provider's refresh token across sign-ins: providers send one on the first consent and usually none afterwards, and a sign-in that returns none leaves the stored one in place. When the framework refreshes an expired access token it stores the result: the new access token and expiry, and the provider's new refresh token when it rotates them.
