On the per-app OAuth 2.1 provider, dynamic client registration accepts only https redirect URIs, or http to localhost/127.0.0.1/[::1], with no userinfo or fragment. Registration is open to anyone, so the scope a client registers is stored as sent and is no limit: it is only the default for an authorize request that names none. The request's scope decides the grant, and the consent page states it: a list of valid resource:action scopes limits the token to exactly that list; no scope, `*` or non-framework names (`openid`) mean full access. (The benmore.ai /mcp OAuth server is the one that keeps only known scopes and narrows a request to the client's registered scopes.) Authorization codes are stored hashed (codes in flight during the upgrade stop redeeming; clients retry). Sign-in matches an existing account's email case-insensitively, and the built-in GitHub provider uses only the account's verified primary email. A `cli_port` CLI login is honored only by the benmore.ai dashboard's built-in providers; an app's own OAuth callback never mints a platform CLI token.
