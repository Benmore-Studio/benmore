Signing in to an EXISTING account by email requires the provider to prove the address. Built-in Google, GitHub and Microsoft keep their own checks (Google's email_verified/verified_email claims, GitHub's verified-email endpoint, Microsoft's tenant-domain check), and managed mode admits only provider-verified emails. A custom app.yaml provider must return a truthy email_verified (or verified_email) claim; otherwise the callback refuses to link and redirects to login with an explanation. Set `trust_email: true` on the provider only when it verifies every address it returns. New accounts from an unverified custom-provider email are still created, but stay unverified (email-keyed memberships, shares and invites do not apply; see api({at:'scoping'}) email_keyed_grants). A verified sign-in to an existing never-verified account claims it for the proven owner and revokes its prior password, MFA factor, sessions and tokens; a grandfathered account (`_benmore_users.email_grandfathered = 1`) is only marked verified.
