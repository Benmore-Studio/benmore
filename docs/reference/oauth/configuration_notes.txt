auth is a scalar-value map; nesting oauth under auth is invalid. Built-in providers use their environment credentials. Custom provider definitions are scoped to the current app, add new names, and do not override built-in definitions. A custom provider's entry under top-level `oauth:` takes the keys `auth_url`, `token_url`, `userinfo_url`, `email_field`, `name_field`, `email_endpoint`, `scopes` and `trust_email`; any other key there is not read, and a write of app.yaml and `benmore check` warn about it. `trust_email` is read as true only when it is written `true`: `yes`, `on` and `1` are read as false (the provider's addresses are not trusted), and the same two checks warn about it. Both CLIENT_ID and CLIENT_SECRET must be present for BYO login controls and routes.
