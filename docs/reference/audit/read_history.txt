GET /api/_audit/reads requires authentication. Ordinary users see only their own read events, ignoring a user_id filter; an unscoped admin can filter another actor. Filters table, row_id and user_id remain parameterized. Limit defaults to 100 and must be an integer from 1 through 1000; invalid, zero, negative and oversized values return 400 before buffered writes or querying. This endpoint returns event metadata, never the read rows' field values: table_name, row_id, query_type, user_id, user_email, client_ip, impersonator_user_id, impersonator_email and created_at. A read made through a support session is an event of the impersonated user with impersonator_user_id and impersonator_email naming the admin (0 and '' otherwise). An unscoped admin sees both; an account reading its own history sees which events were support reads (impersonator_user_id is not 0) with impersonator_email empty and client_ip null on those events, since they are the admin's address and client address.
