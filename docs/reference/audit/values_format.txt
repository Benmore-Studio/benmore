old_values and new_values are TEXT holding a JSON object, with two shapes to allow for when you read them in SQL. (1) The side a mutation does not have is NULL (see absent_values): an insert's old_values and a delete's new_values. Rows written before that hold the empty string '' there, which is neither NULL nor JSON: `json_extract(old_values, '$.qty')` raises `malformed JSON` on them, so a query over older history guards with `json_valid(old_values)` or `NULLIF(old_values, '')`. (2) A single create's (POST /api/<table>) new_values carries the values as bound from the request after type checks, so Int, Float and Boolean columns are JSON strings (`"qty":"5"`, `"done":"1"`), while batch create, NDJSON ingest and /api/_transaction inserts, and update and delete snapshots, are read back from the row (`"qty":5`, `"done":true`). Compare with CAST(json_extract(...) AS INTEGER), not with json_type or a typed literal. Rows written by flows or framework events (account_purge, restore_credentials) may hold NULL on either side.
