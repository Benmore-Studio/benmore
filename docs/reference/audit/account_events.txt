Which account events reach _benmore_audit_log, by `action` (table_name is `_benmore_users` unless named). Recorded: `password_change` (an account changed its own), `required_password_change` (it replaced a temporary one), `password_reset` (a reset link was used), `email_claim_unverified` and `oauth_claim_unverified` (an unverified account was claimed through its verification link or a social sign-in), `passkey_added`, `passkey_removed` and `passkeys_removed_all` (_benmore_passkeys), `mfa_backup_codes_generated` (POST /api/_auth/mfa/setup started an enrollment and issued its backup codes; new_values `{"factor":"totp","count":10}`, and each call replaces the pending secret and codes and writes a row), `mfa_enrolled` (POST /api/_auth/mfa/verify made the factor active), `mfa_removed` (POST /api/_auth/mfa/disable), `mfa_backup_code_used` (a backup code was accepted in place of an authenticator code, at sign-in or as the proof for adding a passkey; new_values `{"remaining": <codes left>}`), `email_change_requested` (the account asked to move to another address; old_values `{"email": <current>}`, new_values `{"requested_email": <new>}`; written when the request is accepted, and kept when the confirmation mail then cannot be sent) and `email_changed` (the change was confirmed; old_values and new_values each hold `email`, and user_email is the address the account held until then), `api_token_created` and `api_token_revoked` (_benmore_api_tokens; row_id is the token's id and the values are its `name`, `scopes` and, when it has one, `expires_at`; a token issued to an OAuth client the account approved is recorded the same way, named `oauth: <client>`), `session_revoked` (_benmore_sessions; DELETE /api/_auth/sessions/{id}, row_id is the id GET /api/_auth/sessions lists and new_values says whether it was the caller's `current` session), `role_changed` (an admin changed an account's role in /_admin), `role_granted`, `role_expiry_updated`, `role_revoked` and `role_expired` (_benmore_user_roles), `impersonate` (an admin started a support session; row_id is the account entered), `act_as_start` and `act_as_end` (_benmore_sessions), `account_purge` (account erasure) and `restore_credentials` (a database restore, which also copies the rows of these events recorded since its snapshot: api(at:"recovery.restore_audit_rows")). On a hosted app, what platform tooling does to accounts is recorded with the platform account as user_email: `superuser_created`, `app_user_created`, `app_user_deactivated` and `app_user_reactivated` (`benmore users <app> deactivate` / `reactivate`; values carry the email and `deactivated_at` before and after), `superuser_promoted`, `superuser_password_reset`, and `data_revoke_session`, `data_delegated_session` and `data_delegated_session_end` for sessions (control_plane).

The row of a second factor, backup code, email change, API token, session or passkey event is written in the same transaction as the change it records: when the row cannot be written the change is refused and nothing changes. user_id and user_email name the account that acted, which for these events is the account affected (a support session cannot perform them). No value is a secret: a row never holds an API token or its hash, a session token, a TOTP secret, an authenticator or backup code, or the token of an emailed link. Addresses are stored as they are in user_email, and account erasure blanks them (api(at:"auth.account_erasure")).

Not recorded: a sign-in, successful or failed, by password, emailed code, social sign-in or passkey; a lockout; a sign-out; a sign-up; a second-factor check with an authenticator code, passed or failed; an attempt at one of the recorded events that was refused (a wrong code or password, a credential that may not make the change); a profile edit other than the email; a session or API token that expires, or that ends with a password change, a reset or an email change (each ends the account's other sessions and its tokens, and its one row stands for that); the second factor an unverified account loses to a password reset or a claim (part of that row); disconnecting a social provider's stored tokens (DELETE /api/_auth/oauth-tokens/{provider}). `compliance: hipaa` adds none of these. The account row carries the last sign-in time (`last_login_at`). An app that must keep a trail of sign-ups and sign-ins records one itself: hooks.yaml hooks on `_benmore_users` fire from the sign-in endpoints (insert on sign-up, update on sign-in and account changes, api(at:"hooks.triggers")), and a hook's `sql:` may INSERT INTO _benmore_audit_log or a table of the app (flow_writes).
