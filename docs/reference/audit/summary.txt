CRUD mutations are captured in _benmore_audit_log with user, action, old/new values, and timestamp. Only writes the framework makes for a caller are captured: a write a flow, hook or cron job makes with its own SQL leaves no audit row unless that SQL inserts one (flow_writes), and sign-ins and second-factor checks are not audit events, while changes to an account's credentials (password, second factor, email, API tokens, sessions, passkeys, roles) are (account_events). Encrypted columns are stored encrypted; hidden columns (see scoping → hidden_columns: *_secret, *_token, credential hashes, password_hash) and their old_* deltas are recorded as "[hidden]", never by value. Enable read auditing with auth.read_audit: '*' or a comma-separated table list (it records list and single reads, `?as_of=` snapshots, `?include=` expansions and /versions reads of audited tables, GET /api/_my-data exports (one event per audited table in the export, query_type `my_data`, no row id), and gotmpl `queries:` SQL and mustache `<query>` tags with query_type `page_query`: one event per audited table the statement reads, including through a join, subquery or view, and per render, so a `<query cache=>` result served from the cache is logged for each viewer; a failed query writes none; an anonymous viewer is recorded only under compliance: hipaa and never on a table whose read mode is anon/everyone, see read_coverage); auth.read_audit_sync: true selects immediate writes instead of the default five-second buffer.
