A submitted foreign-key value (a declared relation, or a column an aggregate computed field follows) must name a parent row the caller can read, on create, on an update that changes it, in batch, ingest and /api/_transaction. A missing and a forbidden parent both answer 422 `<column> references a record that does not exist or is not accessible` (one body for both), so ids of other tenants can't be probed; an unchanged value echoed on update is not rechecked. The answer is the same whatever the parent table's read mode: an id that does not exist in a parent every caller may read (`read: everyone`, a table with no owner or tenant column) answers that 422 too, to an admin as well. Inside POST /api/_transaction an insert's message is prefixed `operation <n> (insert <table>): `, and NDJSON ingest counts the row in `errors`. An aggregate computed field (computed.yaml `sql:` + `triggers:`) is recalculated on the parent a child LEAVES as well as the one it joins, including when the key is set to NULL.
