?col=value is an exact match; ?col__gt= / __gte / __lt / __lte / __ne compare, ?col__in=a,b matches a comma list, and ?col__like= takes a raw SQL LIKE pattern: you write the % and _ wildcards (?full_name__like=Alpha%25 is 'starts with Alpha'; ?full_name__like=Alpha matches only the whole value, ASCII case-insensitively). /api/_query's `like` differs: it wraps the value in %...% (api(at:'query') → text_match). where[col]=v and where[col__op]=v are the same filters. A filter on a column the table lacks or an unknown __op is not applied and is listed in X-Ignored-Params. On a DateTime column a date or date-time value is compared as an instant, whatever spelling the row was stored in (datetime_filters).
