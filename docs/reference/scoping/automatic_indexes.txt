At boot and hot reload the framework creates non-unique `idx_bm_<table>_<cols>` indexes on scoping columns: user_id, the tenant key, foreign-key columns, the membership table's user field and each member-of (join, user) pair, skipping a column an existing non-partial index already leads with. They are additive and never appear in migration files or promote's diff. A raw ALTER TABLE ... DROP COLUMN on an indexed column (sql write is DML-only; this applies to custom SQL tooling) must drop that idx_bm_ index first; migrations, prune and custom-field removal do it themselves. The first boot after upgrade builds them while holding the write lock.
