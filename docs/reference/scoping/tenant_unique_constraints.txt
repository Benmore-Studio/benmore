A unique constraint on a table that carries the groups: key is enforced by SQLite across EVERY tenant unless it includes the key: `email String @unique` on a tenant table means no two tenants can hold the same email, and a create or update that collides with another tenant's row is refused. The refusal is the same generic 'a record with the same unique value already exists' whether the other row is in the caller's tenant or not (constraint and column names are never shown), but it still tells a tenant the value exists somewhere. Scope it: `@@unique([orgId, email])`. benmore check and the post-write check warn about @unique / @@unique on a tenant table that leaves the key out (warning only) - keep a global constraint only when the value really is unique across tenants.
