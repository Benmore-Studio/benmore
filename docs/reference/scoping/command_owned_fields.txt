A command flow may declare `command.owns: [table.column, ...]` (columns of tables in its `writes`). Generic auto-CRUD then refuses any request naming such a column with 403 {"error":"field_owned_by_command","field":"table.column","command":"<name>"}, for every caller including admins, on create, update, singleton upsert, batch, ingest, /api/_transaction, /api/_groups/create, the admin panel, workflow transition of an owned state column (GET /api/<table>/<id>/transitions then lists no move), bulk import Mode A and the native connector update; a version revert leaves owned columns unchanged. An UPDATE that echoes the stored value is allowed only for a caller who can read that column (a changed or unreadable value is refused); deleted_at and updated_at cannot be owned. Other columns of the same table stay editable and creating a row without the field uses the DB default. The admin panel's create form has no input for an owned column and its edit form shows the value read-only. The declaration takes effect whether or not an mcp.yaml binds the command flow. Ownership constrains generic CRUD only: other commands, flows, hooks, cron, operator SQL and Mode B SQL restore can still write the column. See api({at:'connector'}) (connector_grants).
