GET /api/<table>?sort=<col>&order=asc|desc (asc by default), or ?orderBy=<col>[:asc|desc] when sort is absent (its direction overrides order); without either the list is newest id first, and a cursor page (?cursor=) is always ordered by id. A sort parameter the list does not apply is listed in the X-Ignored-Params response header next to unknown filters: `sort`/`orderBy` naming no column (`sort=-name` is not descending: write order=desc), an order other than asc/desc (applied as asc), orderBy beside sort, order with no sort, order_by (not read), and any sort on a cursor page. A sort that is refused is not listed there: a hidden column answers 400, an encrypted column 400, a blind-index sibling 403 for a caller without unmask rights. A DateTime column sorts by instant, not by stored spelling; created_at and updated_at keep the plain, index-served sort (datetime_filters).
