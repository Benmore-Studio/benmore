groups.user_field names the member. A column whose name contains "email" holds the member's address (and counts only for a verified or grandfathered account, see email_keyed_grants); any other column holds the member's user id (_benmore_users.id), which is what POST /api/_groups/create writes there. An id-keyed membership resolves the tenant at sign-in and on later requests, and loads groups.role_field for it. A user with several live memberships lands in the oldest. A column that holds addresses under another name (say `login`) keeps resolving by the account's email, but only for an account whose address is verified or grandfathered, the rule an email-named column follows. Name the column with "email" in it so POST /api/_switch_group and the group user directory work for it too.
