POST /api/<table>/<id>/restore or bm.table(table).restore(id) restores only that row when deleted_at exists. It requires read and update policies/scopes before mutation, applies row/tenant/ACL authority to the deleted row, honors locks and command-owned fields, rechecks parent visibility, runs canonical validation/hooks/audit/versioning, and returns the sanitized row. It clears only deleted_at; request body fields cannot change ownership or data. Missing, live or out-of-scope rows return 404. Children stay deleted. Restoring a tenant membership cannot bypass membership management or reactivate a caller outside the row tenant. An overlapping authored HTTP/command route keeps ownership; the native restore route is omitted for that table.
