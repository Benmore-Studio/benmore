String form `verify: stripe | github | github_sha256 | shopify | slack | benmore` (or a header name) plus a sibling `secret:` on on.request runs that provider's canonical check. `verify: benmore` checks a delivery from another Benmore app's webhook subscription (see `outbound_signature`) with the subscription's secret as `secret:`. The write gate and `benmore check` refuse `secret:` with no `verify:` (nothing would check a signature, so the route would answer unsigned requests), a string `verify:` with no `secret:` (every request would get 401), and on.request `secret:` beside a map-form `verify:` (not read; the map's own secret is used); a deployed file still loads and logs the problem. A literal webhook signing secret (`whsec_...`, Shopify `shpss_...`) in any pushed file is refused like other provider keys: set it with `benmore env` and write `secret: "${{ env.NAME }}"`. A header name (hyphen-joined, such as `X-Webhook-Signature`) checks that header, and only that header, for hex(HMAC-SHA256(secret, exact raw body)), with an optional `sha256=`, `v1=` or `sha1=` prefix; it has no timestamp, so prefer a provider or `hmac_timestamp_dot_body` where the sender supports one. `Authorization: Bearer <secret>`, `X-Webhook-Secret: <secret>` and a body HMAC in any header other than the named one are not accepted. The write gate and `benmore check` refuse any other value with a did-you-mean (a provider typo, a provider's own signature header such as `Stripe-Signature`, a recipe name written as a string); a deployed file still loads and logs it, and its requests get 401 unless they carry the named header's HMAC; its `secret:` takes `${{ env.NAME }}` or `{{env.NAME}}`, and a secret that doesn't resolve (unset variable) rejects every request (401) rather than using the template text. The map form `verify: { recipe: … }` works the same way - see api({at:'verify'}). A verified flow binds nothing from the URL query string (no verifier signs it), so replaying a signed event to `?id=evt_other&type=...` does not replace its `:id` / `:type`, and `INSERT OR IGNORE` dedupe holds; path parameters still bind. See api({at:'verify'}) → signed_input.
