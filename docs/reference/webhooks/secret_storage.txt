A subscription's signing secret is stored sealed (AES-256-GCM) under the app's ENCRYPTION_KEY, and every delivery opens it to sign. An app with no configured ENCRYPTION_KEY and no encrypted fields runs on a key generated for the process, which would not survive a restart, so creating a subscription first saves that generated key to the app's env.yaml (the line an app with encrypted fields gets at its first start) and seals only when the environment the next start reads resolves that key. When it cannot (env.yaml is not a writable regular file, or the app's environment sets a different ENCRYPTION_KEY) the create answers 503 `{code: "encryption_key_not_durable"}` and stores nothing: set ENCRYPTION_KEY, restart, create again. A subscription whose secret the app's key cannot open (sealed under a key that was lost, or a key changed without the rotation workflow) is listed with `status: secret_unreadable` and a `fix` text, is named in a startup log line, and each of its deliveries fails once with that reason instead of retrying. The secret cannot be recovered: DELETE the subscription and create it again with the secret your receiver verifies.
