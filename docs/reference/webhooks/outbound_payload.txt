Envelope: `{event, table, data, timestamp, triggered_by, triggered_by_user_id}`; triggered_by is the actor's email and triggered_by_user_id the actor's user id, both absent for a write with no signed-in caller (an anonymous write). `data` is the changed row (plus old_<col> deltas on update) without hidden columns (scoping → hidden_columns: *_secret, *_token, credential hashes); a receiver that needs such a value must be sent it by a flow that selects it by name. A column of the table always carries the row's own value, so when an admin edits alice's ticket `data.user_id` is alice's id, as stored. The actor's user_email/user_id/user_role/user_roles/user_group_id appear in `data` only under names the table has no column for. Hook SQL `{{user_id}}`, `when:`, notification/email/SMS/ws templates, a hook `webhook:` default body and event flows read the actor under these names. An insert's `data` is also the row as stored, read back after the insert, like an update's: typed values (`"amount_cents":2500`, not the submitted text) and the columns the database filled in (a `status` default, created_at, updated_at), for single, batch and /api/_transaction creates alike. `data` never carries the internal flags `user_admin_bypass` and `user_act_as_group_id`; hook SQL and templates read them.
