A signed URL cannot be recalled. Whoever holds it can fetch the file until its lifetime ends or the object is deleted, whichever comes first. Deleting the file (`run: delete_upload`, api({at:'uploads'}) → private_deletion) ends every link to it at once: the media CDN answers 403, local storage 404. Nothing else ends a link early: deleting or revoking an app-level share (a share row or token your own flow checks), changing the record's access rules, signing the user out or erasing their account with a flow's `run: purge_current_user` step stops NEW links from being signed, and a link already given out keeps working until its own expiry. An account deletion that runs no app flow (/settings/delete-account, and an operator's `benmore users <app> delete` or MCP delete_app_user) deletes the private files the account uploaded, except those it uploaded as an admin, so every link to a deleted one ends with it (api({at:'auth'}) → account_erasure_files). So sign for as short as the use needs (bm.signedUrl defaults to 5 minutes, `run: serve_file` to 2 minutes; see lifetime) and sign at the moment of use rather than storing links. For a share that must stop working the moment it is revoked, do not hand out a signed URL at all: serve the bytes through a flow that checks the share on every request and ends in `run: serve_file`; on the media CDN use `disposition: attachment`, which streams the file through the app so that no signed URL reaches the caller (api({at:'flows'}) → serving_private_files).
