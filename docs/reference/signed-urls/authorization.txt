PRIVATE-file signing is an AUTHORIZATION decision, not just 'are you logged in'. You MUST pass the owning record - `{ record: { table, id } }` (→ record_table/record_id). The framework authorizes the signature against THAT record's full access policy: access mode (anon/role:/perm:/admin/group/owner), RBAC scope union, group + owner + ACL + tenant-scoped grants - the SAME decision as GET /api/<table>/<id>. If you can't read the record, you can't sign its file (403). It also verifies the record actually references the file (no pairing a readable record with someone else's path). So a leaked/guessed private URL is useless without an authorizing record, and org/tenant isolation is inherited from the record's policy - exactly what you'd get reading the row. A soft-deleted or missing record authorizes nothing, even on an `anon`/`everyone` table. Public files need no record and no signature. Local-disk files (self-hosted) use an HMAC URL bound to the request host instead of a CloudFront signature, with the same rule: a private file needs its record (403 without one), a public file does not.
