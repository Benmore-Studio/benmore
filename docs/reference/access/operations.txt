Op keys: `read` (list, single-row read, versions, include; a single-row read GET /api/<table>/{id} returns exactly the rows the list would, including anon/everyone reads and public_read_when rows), `write` (CREATES only: POST, batch create, ingest, import), `update`, `delete`, and `all` (fallback for any op not listed). Resolution per op: the table's op key → the table's `all:` → `default:` (same order) → the implicit default. update and delete do NOT inherit from write: `orders: { read: group, write: admin }` leaves update/delete at the implicit default (`group` on a tenant table - any member may edit), so declare them or use `all:`. Beside the ops a table takes one switch, `share: on|off`, which turns record sharing on or off for that table (api({at:'permissions.sharing_switch'})); it is not an op and takes no mode. Any other op key (`create:`, `list:`, `edit:`) is never read; the write gate and `benmore check` refuse it.
