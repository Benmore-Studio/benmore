A configuration whose routes cannot be registered does not crash the app. Two routes cannot share one pattern. When two framework routes collide (a table named like a framework path such as `_upload`; two workflows on one table are refused earlier, when workflows.yaml loads: api(at:"workflows") one_per_table), startup exits with `route registration failed: pattern ... conflicts with pattern ...`, naming the route. A reload is rejected with that error, and the previous configuration, background workers and handler keep serving; `benmore check` reports the same text as a `routes` error. Schema changes the reload had already committed are not undone: a table that collides must be renamed or dropped in the database, not only removed from the schema. A flow whose route collides is skipped with a log line (api(at:"flows") route_collisions).
