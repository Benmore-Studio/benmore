Startup and reload reject malformed app.yaml, hooks.yaml, flows.yaml/flows/*.yaml, workflows.yaml, cron.yaml, encrypted.yaml, env.yaml, and the generated environment file before the database is opened or migrated. app.yaml checks include backup duration/retention and the shapes of auth, roles, access, groups, scopes, and encryption settings. Missing optional files deliberately remove their configuration; unreadable files are errors. Backups require interval >= 1m and a positive integer keep (default 20). Legacy root flow maps load alongside GHA flow files, but new writes require the GHA form. Cron accepts a jobs list or named-job map, with flow or inline run/steps; invalid or partially parsed jobs fail the load. Fix the named file and retry the push/reload. This does not roll back schema changes already committed by an earlier operation. The write gate and `benmore check` also refuse an app.yaml key nothing reads: an unknown top-level key, and an unknown key under auth:, csp:, groups: or features:. The refusal lists the keys that exist. A key nothing reads in the other sections with a fixed set of keys is accepted, so an app that carries one still pushes and deploys, and a write of app.yaml and `benmore check` answer with one warning for each, naming the nearest key that is read and the keys of the section: `seo:`, `pwa:` and `recording:`, and each entry of `roles:` (`scopes`, `inherits`), `auto_memberships:`, `scopes:` and `oauth:`. The same warning covers a value that is not read: `theme:`, `mode:` or `css:` set to a value that is not one of theirs (api({at:'ssr'}) appearance), and `site_name:`, `theme:`, `mode:`, `font:`, `brand:` or `css:` written as a list, a mapping or a bare number instead of text. A `features:` switch takes true or false (yes/no and on/off mean the same). One written as a mapping is accepted and read by its `enabled:` value alone: `uploads: {enabled: no}` is off, and a mapping without an `enabled:` that says true or false counts as on, except `ws_anonymous`, which stays off. Its other keys are not read, and the same warning says which state the switch is in. `benmore validate-write` prints these warnings for the content it is given before anything is saved (api({at:'harness'}) edit_hooks).
