A served app sets its Go memory limit from its own cgroup v2 memory limit (a percentage of `memory.high`, or of `memory.max`, never below 64 MiB) and logs it as `memory: Go memory limit <n> MiB ...` at start and on each change. On the hosted platform the limit is the platform's: GOMEMLIMIT, MALLOC_* and GLIBC_TUNABLES are reserved, so an app's env cannot set them. Self-hosted `benmore serve` (the framework edition, a container, bare metal): an explicit GOMEMLIMIT wins and is logged as `memory: Go memory limit stays GOMEMLIMIT ...: outside the hosted platform an explicit GOMEMLIMIT wins over the cgroup (...)`; without one the cgroup value applies as above. No-op off Linux, under cgroup v1, or with no limit on the path, where GOMEMLIMIT applies. Native memory: glibc malloc arenas are capped at 2. A non-empty MALLOC_ARENA_MAX, or a `glibc.malloc.arena_max` entry in GLIBC_TUNABLES, in the process environment of a self-hosted app wins.
