`benmore push` and `benmore deploy` exit non-zero when the platform saved the files but its post-write source check reports errors (the write answers `ok: false` with `error_summary` and the findings under `check`), for example two flows on one route, or a cron.yaml job naming a flow the write changed. They print `✗ the files are saved, but <app> has N error(s) to fix` and one `✗ [file (source)] message` line per error, then exit 1 (2 from the save hook); deploy ends with `✗ files deployed, but <app> has the errors listed above` instead of `✓ deployed`. A single write's own check is the verdict. In a batch (deploy, or a push of several files) a later file can resolve what an earlier one reported (a schema ahead of the flows that follow it, two flows swapping routes), so the CLI calls check_app once after the batch and fails only on the errors it still reports (leaving out its app_load and app_live findings, which the reload wait reports); when check_app cannot answer, it fails on the errors the writes reported. Warnings never fail a push or deploy. The files stay saved: fix the source and push again.
