Dashboard reset (POST /platform/app-reset-seed?app=<sub>&env=dev|prod&confirm=true) and MCP reset_and_seed require editor access to the selected app. The CLI form is `benmore reset-seed <app> --env dev|prod --confirm`: it calls the dashboard endpoint, and refuses (exit 1, nothing sent) without `--confirm`, or when neither `--env` nor a `benmore use` pin names the instance. The dashboard endpoint refuses (400) a request without an explicit env=dev|prod; MCP reset_and_seed refuses when env is omitted and the app has no dev instance (the default would be production). They atomically clear ordinary app tables and execute seeds.sql. Missing/empty seeds intentionally mean clear-only. Read, deletion, seed, cancellation or foreign-key failure rolls back the reset and returns an error. Counts describe committed results only. Framework _benmore_* tables and generated version history are preserved; virtual/shadow search tables are maintained by source-table triggers. Seed SQL supports app-data INSERT/UPDATE/DELETE/REPLACE and CTEs, with quoted semicolons and comments; it cannot manage transactions, change schema/connection settings, attach another DB or mutate framework tables. This privileged maintenance operation runs SQLite triggers, not ordinary per-record CRUD hooks; do not use it as an application mutation API. A successful reset is destructive and requires a separate backup for later recovery. The testing-mode reset (POST /api/_testing/reset, the admin panel's Reset & Reseed button; needs features.testing with DEMO_PASSWORD, an app admin on an unscoped credential, and CSRF) runs this same reset, with the same seed rules. A refused or failing seed answers 422 {status:"failed", seeds:false, error} naming the statement by number (never its text) with no data changed; any other failure is a 500 with a request id, also with no data changed. Success answers {status:"reset", seeds:true, tables_cleared, seeds_run} ({status:"cleared", seeds:false} when seeds.sql is missing or empty) and writes a data_reset_seed audit row for the admin. On every reset path, an app whose audit tables are append-only (compliance: hipaa) refuses a seed statement that names one, reads included: see api(at:"audit") -> append_only.
