A write is saved when write_file/edit_file answers but goes live only when the app's hot reload runs, normally 5 s after the last write. The platform defers that reload when the instance reloaded 5 times within 60 s (`loop_limit`: it waits for the end of that minute, about 65 s) or when its previous reload was slow (`spacing`: up to 3x that reload's time, at most 2 minutes). The write answer carries `reload: {scheduled_at, delay_seconds, reason, deferred, message}` (reason `debounce`, `loop_limit` or `spacing`; no `reload` when the write queued none, as with `reload: false`); until scheduled_at the app serves the previous version. `benmore push` and `benmore deploy` print that the push is saved but NOT live yet, when it will be and why, then wait for the reload (up to 3 minutes) and print when it is live; a reload still not seen after that keeps the not-observed warning (exit 0). The Claude Code save hook (`benmore push --from-claude-hook`) does not wait, because its time limit is shorter than the deferral: it prints the same message and exits 2 so the agent reads it; the file is saved and nothing needs fixing. Fewer, batched pushes (`benmore deploy` reloads once per batch) avoid the loop limit.
