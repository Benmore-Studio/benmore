The file tools (read_file, write_file, edit_file, delete_file, get_schema, upload_static, upload_static_from_url, upload links, the dashboard and workspace file views and the icon upload) work only inside the app's own directory. A symbolic link in the app that is relative and stays inside the directory works. A link that points outside the app, or any absolute link (even one that points back into the app), is refused with `path escapes app directory`: replace it with the file itself or with a relative link. Uploads are refused while static/ itself is a link out of the app. File listings show a link as one entry and do not walk into it. .git/, .benmore/, env and secret files and data.db are unavailable through these tools. Where the platform operator has locked tenant data, uploads/ is refused too ("the router does not open app data while the tenant data lock is on"). write_file bytes sent as `content_b64` that are UTF-8 text are validated exactly like `content`; other bytes still get the forbidden-path refusals and the committed-secret scan, and a source file (.ts/.tsx/.js/.jsx/.mjs/.html/.yaml/.json/.prisma/.sql) gets the full write gate. upload_static, upload_static_from_url and upload links take assets only: scripts and pages (.ts/.tsx/.js/.jsx/.mjs/.cjs/.html) are refused (write them with write_file), and every upload is scanned for committed secrets. A write (write_file, edit_file, `benmore push`, `benmore deploy`) of a file that holds a literal provider credential is refused, naming the kind: a Stripe secret or restricted key, a webhook signing secret (whsec_), a Shopify app secret or access token, an AWS access key id, a GitHub token, a Google API key, a Slack token, a Resend, Anthropic or OpenAI API key, or a private key block. Set the value with `benmore env <app> set KEY=VALUE` and read it as `${{ env.KEY }}`; a publishable key (pk_...) is accepted.
