The banner (Accept / Decline, stored in the bm_cookie_consent cookie as accepted|declined for a year) appears whenever analytics is on. Its default text describes only the framework's analytics. An app that adds its own trackers (Google Analytics, ads pixels) must say so: set seo.cookie_notice in app.yaml to the banner text (plain text), and seo.privacy_url to a same-origin path or https URL to add a Privacy policy link. Load those trackers only after consent: window.bmCookieConsent() returns the current choice, document fires a bm:cookie-consent event (detail = the choice) when it changes, and window.bmCookieSettings() reopens the banner, e.g. from a footer 'Cookie settings' link, so visitors can withdraw consent. A PDF from GET /pdf/<page> carries neither the banner nor the beacon; window.bmCookieConsent() returns '' there. The framework's own `font:` setting loads Google Fonts, which sends visitors' IP addresses to Google; self-host fonts in static/ if that matters for your users.
