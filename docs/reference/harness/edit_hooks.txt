The Claude Code hooks that `benmore hooks` installs run two commands on Edit, Write and NotebookEdit. Before the edit, `benmore validate-write --from-claude-hook` reads the hook's JSON from standard input, builds the file as the edit would leave it and runs the platform's write validators on it without writing anything (the `write_file` tool with `dry_run`); a refusal prints the validator's message on stderr and exits 2, which blocks the edit and shows the agent the reason. After the edit, `benmore push --from-claude-hook` ships the file. Both exit 0 without doing anything for a tool that does not write, a file outside any app folder, and env, secret or framework-owned paths. By hand, in any agent: `benmore validate-write <path> [--content-from-stdin] [--app NAME] [--app-dir DIR]` validates the file on disk, or with `--content-from-stdin` the bytes on standard input as that path's content; a path whose file does not exist exits 0 without a check. The app is `--app`, else the .benmore/app marker of the app folder (`--app-dir`, else the nearest folder above the path that holds app.yaml or schema.prisma), else that folder's name. Exit 0: the validators accepted the content; 1: they refused it (message on stderr); 2: a usage error. Run by hand, an accepted file still prints on stderr the warnings its content alone decides, each with its `docs:` address, and exits 0: for app.yaml the keys and values that have no effect or are not read, for a tests/*.yaml file what `benmore test` cannot load. The `write_file` tool with `dry_run` returns them as `check.findings`. Warnings that compare the file with the rest of the app (a table that does not exist, a role no table names) need the saved file: the push and `benmore check` report those. For app.yaml the dry run says so itself: its answer carries `checks_after_save`, and the command prints that line after the warnings, also when there are none.
