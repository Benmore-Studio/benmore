`probe_route`, `benmore probe` and an `api` call follow a redirect only while it stays on the app's own backend (a path such as `/login`; a chain still redirecting after 10 requests fails) and return the first redirect that points anywhere else as the app answered it: the 3xx status plus `location`. Anywhere else includes a sign-in provider, a payment page, the media CDN, and the app's own public address written out in full (`https://<app>.<domain>/login`); probe that path yourself to continue. A redirect to an owner-only `/api/_internal/encryption/` path is returned unfollowed too. The probe's CSRF fetch (GET / before a mutating probe) follows the same rule, so an app whose home page redirects off the app gets no auto-attached token. Under `benmore host` no redirect is followed; the result carries `location` there as well.
