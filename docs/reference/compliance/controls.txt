Each line is added by the change that ships the control. (1) Idle logoff: auth.idle_timeout defaults to 15m and may only be set between 2m and 15m (see api(at:"auth") -> idle_timeout). (2) MFA for every account: auth.require_mfa_for_roles defaults to "*" (every role, including an account with none) and a list without "*" is refused; enrollment is TOTP (a passkey is not a second factor for this rule), enforced on every credential of the account as for a listed role (api(at:"mfa") -> existing_credentials). (3) Append-only audit: BEFORE UPDATE/DELETE triggers on _benmore_audit_log and _benmore_read_audit abort every change, and a BEFORE INSERT trigger refuses an insert naming an existing id (REPLACE), while an ordinary INSERT by the running app (a flow's or hook's SQL) is still allowed; flow, hook and page SQL that would UPDATE or DELETE an audit row, or drop or change one of these triggers or tables, is refused before it runs, so the rule does not depend on a trigger being in place; the triggers are checked against their exact text and restored at every start and reload, and a user migration or seeds.sql statement naming an audit table is refused whatever it does, an INSERT included; a migration also cannot set `PRAGMA writable_schema`, and for a hipaa app cannot change the audit tables, their triggers or their rows whether or not the triggers are in place. The framework's own maintenance (retention sweep, account erasure scrubbing, legacy session-id rekeying, the test runner's setup SQL) lifts them inside its own transaction and restores them before commit; sql(write:true) may not name an audit table; BENMORE_AUDIT_RETENTION below 6 years is ignored. See api(at:"audit") -> append_only. (4) No GitHub sync: linking a repository, and every later push, is refused when the app is hipaa (either app.yaml, or the platform's record); an already-linked app is switched off at its next push with the reason in `last_error`, while an app.yaml that cannot be read or parsed refuses only that push (api(at:"github") -> hipaa). (5) No production data in dev: refresh_dev with data (--with-data or --data-only) is refused for the app (dev-only code refreshes still work, and seed_dev starts dev with an empty database), and the session recorder is off in dev and prod: `recording.enabled: true` / `recording.production: true` are refused (api(at:"environments") -> hipaa). What these controls leave to the app (its flows' own writes and responses, token scopes on pages, account events, a patient's export): not_covered.
