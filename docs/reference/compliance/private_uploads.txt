Under compliance: hipaa every upload is private (served only through a signed URL, api(at:"signed-urls")): POST /api/_upload without `kind` stores under uploads/private/, an explicit public kind (anything but `private`) answers 400, and POST /api/_files and multipart auto-CRUD creates store under uploads/private/_files/ and uploads/private/<table>/. The write gate and `benmore check` refuse app source that asks for a public kind as a literal in an upload call (`bm.upload(f, {kind: 'avatars'})`, or `formData.append('kind', ...)` / `<input name="kind" value=...>` in a file that sends to /api/_upload or /api/_files); a kind built at run time is caught by the 400. Not covered: the built-in sdui upload field, FileField and Uploader previews put the stored /uploads/private/... reference straight into the link or image, which answers 403 unsigned (on the platform media CDN bm.signedUrl needs the owning record, which a create form does not have yet); show stored files with SignedImage or bm.signedUrl(path, {record}). Files uploaded before the app turned hipaa on stay where they are (public); move them yourself. See api(at:"uploads") -> hipaa.
