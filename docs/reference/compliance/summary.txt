Top-level app.yaml `compliance: hipaa` is one opt-in enum (unset = the ordinary defaults; any other value is refused by the write gate, `benmore check` and the loader). Under it the stricter defaults listed in `controls` apply, and an app.yaml that sets `compliance: hipaa` while explicitly weakening one of them is refused at write time and in `benmore check`. It is a set of safeguards the framework can enforce, not a certification: BAAs and the remaining gaps are an operator and legal matter. The switch only turns on: the first time the platform sees `compliance: hipaa` in the prod or dev app.yaml (at a deploy, promote, GitHub push, refresh_dev or an app.yaml write) it records the app as hipaa, and from then on the platform's refusals (GitHub sync, refresh_dev data copies) hold even if the key is deleted, the write gate and `benmore check` refuse an app.yaml without the key, and promote refuses a dev app.yaml without it (also when only prod's app.yaml has it). Only a platform operator clears the record (release runbook, "HIPAA compliance record").
