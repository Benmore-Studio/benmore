Gotmpl `queries:` SQL and mustache `<query>` tags (`sql=` and the `from=` shorthand) can return any expression, so unmask needs proof. A global decision (admin bypass, a global unmask role, a field with no unmask roles) always applies. Owner (`self`/`owner`) and tenant-role unmask apply only when the query has one SELECT over one table with no join, and only to that table's fields. Owner also needs one of: `user_id` selected as itself (or `*`), page `scope: owner` (`<page scope="owner">`), or a top-level `WHERE user_id = <the viewer's id>` with no OR, BETWEEN or CASE in the clause. In gotmpl that value is `:user_id`. In a `<query>` tag it is any template value whose bound argument equals the viewer's own id (`{{user_id}}`, `:current_user`, shorthand `owned="true"`); a request value naming another user, a numbered or named SQL parameter, or a placeholder count that does not match the arguments proves nothing. Tenant-role unmask needs the tenant column selected as itself. /api/_query adds these columns internally; authored SQL cannot be rewritten, so add them to the SELECT. Everything else masks, including an owner's own row in a join. An enc:v2 value follows the field it was sealed for under any alias and when copied into an ordinary column. A v1 or context-free value must pass every encrypted field the statement read, and masks when the statement read none. A non-ciphertext result named like an encrypted column the statement read is masked by that field's policy, including an ordinary column of the same name in a join (alias it to avoid this). Limit: `benmore_decrypt(col) AS other_name` returns plaintext under a name that matches nothing; calling that function in page SQL is the author choosing to show the value. A `<query cache=>` result holds the masked rows, so it is shared only by viewers with the same access to every declared field (api({at:'frontend'}) query_tags).
