A computed.yaml column (`expr:` or `sql:`) that encrypted.yaml (or app.yaml `encrypted:`) also encrypts is stored as ciphertext. The computed trigger seals the value itself, bound to the field like the encryption trigger's ciphertext, keeps a `blind_index:` sibling current, and writes only when the stored ciphertext does not already hold the computed value. Reads decrypt and mask it like any encrypted field; key rotation re-seals it; on a versioned table an `expr:` field's recalculation adds no version, as for an unencrypted one. Values stored by an older runtime stay plaintext until their row is next written; to seal them at once run `benmore sql <app> "UPDATE <table> SET <column> = <column>" --write --confirm` (without `--confirm` it only previews). The expression itself must read only unencrypted columns (computed_aggregates). Encrypting a value derived from plaintext columns protects it at rest only as far as those columns are protected.
