A masked value is always the string `****`, whatever the plaintext: every non-NULL value of a field the viewer may not unmask reads `****`, including an empty string and the values of INTEGER, REAL and BOOLEAN columns (a masked number or boolean is the string `****`, not a number, so typed client code should treat a string there as masked). NULL stays null. This applies wherever a field is masked: auto-CRUD reads, includes and create readback, `/api/_query`, versions, exports, realtime events, connector command reads, gotmpl `queries:` and mustache `<query>` tags. A last-four display (card numbers) is not a mask mode: store the last four in their own unencrypted column (e.g. `card_last4`) and encrypt the full value. `[unavailable: decryption failed]` is a different value: a key problem, not a mask (see gotchas).
