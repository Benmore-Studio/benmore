A flow's SQL step reads the table directly. Encrypted columns arrive decrypted and nothing is masked for the caller, so what a `respond` step returns is what every caller the flow admits receives: a role that reads `****` through the API reads the value through the flow. `SELECT *`, `t.*` and `RETURNING *` on a table with encrypted fields return every encrypted column in clear. For a blind-indexed column the step's rows also hold its `<col>_blind` value (blind_index: an HMAC that is equal for equal plaintexts), which the steps of the flow can read and bind (`steps.<id>.outputs.first.<col>_blind`) and which a `respond` step leaves out of what it sends: a key named like a blind column the app declares in `blind_index:` (on any table) is dropped at every depth of the response, in a `json` body, a body that is one reference, a list or object rendered into a text body or a header (`| json` included), and a key written in the step's own `json:`. Every other column of the row is sent as before. A column that only ends in `_blind` and is declared nowhere is an ordinary column and stays. To return the value on purpose, select it under another name (`SELECT ssn_blind AS match_key`) or reference the single value under another key (`match_key: ${{ steps.p.outputs.first.ssn_blind }}`). Steps that send data elsewhere (`run: api`, `webhook`, `email`, `sms`, `enqueue`, `broadcast`, `notify`, a `redirect` target) send what they are given. Select the columns the response needs by name (`SELECT id, name, dob FROM patients ...`), leave an encrypted column out unless every caller of the flow may read it, and put the flow's own authorization in its WHERE clause. An expression over an encrypted column inside SQL (`substr(ssn, -4)`) works on the stored ciphertext, not the value. Under `compliance: hipaa`, `benmore check` and the check after a push or file write warn when a `respond` step returns a SQL step's rows whole (`steps.<id>.outputs.first`, `.rows`, `.rows[0]` or `.outputs`) and that step's query selects `*` from a table with encrypted fields; the message names the encrypted columns the response carries in clear. It is a warning: the file is accepted. A response that reads single columns (`steps.<id>.outputs.first.name`), a query that names its columns, and a row handed on through `run: set`, a loop variable or another step are not reported, and an app without `compliance: hipaa` gets no warning.
