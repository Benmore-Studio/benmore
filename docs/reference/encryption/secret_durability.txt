Framework secrets the app reads back later, webhook subscription signing secrets and OAuth provider tokens, are sealed only under a key that survives a restart. Without a configured ENCRYPTION_KEY (and without encrypted fields, which save one at first start) the app runs on a key generated for the process. The first such secret saves that key to env.yaml (0600; 0640 in a hosted app) and seals only when the environment the next start reads resolves it; from then on the key is durable for every sealer, and TOTP secrets are sealed at the next start. An MFA enrollment, or the next successful use of an unencrypted TOTP factor, saves the key the same way (`api(at:"mfa")` secret_storage); there a key that cannot be saved leaves the TOTP secret unencrypted rather than refusing enrollment. When it cannot be saved nothing is sealed: a subscription create answers 503 `encryption_key_not_durable`, and an OAuth sign-in still succeeds but its provider token is not stored (logged). A value sealed earlier under a lost per-process key cannot be recovered: re-create the subscription (`api(at:"webhooks")` secret_storage); the user signs in with the provider again. Set ENCRYPTION_KEY yourself before storing such secrets when you want to choose the key.
