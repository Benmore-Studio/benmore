check_app / benmore check refuses configured encrypted fields without a durable ENCRYPTION_KEY before opening or migrating the database. Validation never creates that key. Initialize the key through the app's startup/environment workflow, then validate again. Standalone startup still auto-generates a missing field-encryption key; hosted restart preparation is described in hosted_restart. Validation with an existing configured key keeps its normal migration and trigger checks. This does not make all app validation read-only.
