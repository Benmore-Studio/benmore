Reload installs encrypted-field triggers, blind-index columns/triggers and version-history policy in one transaction before publishing the new configuration. Installation failure keeps the prior policy. The configured durable ENCRYPTION_KEY must match the running database key; initialize encryption through an app restart when no durable key is active, and use the key-rotation workflow for existing encrypted data. Enabling a field protects subsequent writes; existing source rows still need the encryption backfill workflow. Earlier backups and WAL/free-page remnants are separate artifacts.
