A hosted restart (CLI, dashboard or MCP) loads the instance's current environment first. If encrypted fields were newly added and no key is set, the platform creates and stores an ENCRYPTION_KEY for the instance; the app needs no env.yaml for it. Existing configured keys are retained. If the environment cannot be prepared, the restart does not happen and the app keeps its previous environment. A reload does not re-read the environment; a restart does. An unreadable or malformed env.yaml is an error: a key is never discarded or replaced to make validation pass. A push that declares encrypted fields while the running environment holds no ENCRYPTION_KEY schedules a restart (which sets a key first) instead of a hot reload.
