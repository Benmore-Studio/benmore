encrypted.yaml (or app.yaml encrypted:) naming a table the app does not have is refused at push and by benmore check; a misspelled table leaves the real one in plaintext, and the runtime cannot load the declaration. A column the table does not have (a blind_index field included) is refused the same way. The load refuses both (`encrypted field <table>.<column>: source column does not exist`): a reload keeps the previous configuration only until the app next starts, and a push that turns on the app's first encrypted field restarts the app at once, so it stopped serving straight away. A column counts when schema.prisma declares it (the field's @map, else its snake_case name) or one of the app's migrations/*.sql adds it; a table a migration creates is accepted without checking its columns. A schema.prisma write that removes a model or field encrypted.yaml still names is refused too: remove it from encrypted.yaml first, or deploy both together; see api(at:"schema") → config_references. A framework table (`_benmore_*`, `sqlite_*`) is refused as well: api(at:"schema") → framework_tables.
