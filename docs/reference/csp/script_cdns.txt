unpkg.com, cdn.jsdelivr.net, esm.sh and cdn.skypack.dev are in script-src and connect-src only for an app whose source names that host - a `<script src="https://cdn.jsdelivr.net/...">`, an `import x from 'https://esm.sh/...'` in a .tsx module, an import map, a URL a bundle builds. The runtime scans the app directory (static/, root pages, partials, layouts, flows, app.yaml and other source; not tests/, docs/, migrations/, uploads/, hidden directories, root Markdown, .d.ts files, databases, env files or binary media). Any mention counts, edits are picked up within about a second (a hot reload refreshes at once), and an app whose files cannot be scanned keeps all four. So does a response sent before a scan has finished: the first page response after the app starts, and one sent while changed files are being re-read, list all four, so read the header from a later response. An app that imports sdui gets only the Leaflet 1.9.4 files the `Map` component loads (script, stylesheet and marker images, pinned with Subresource Integrity), not the unpkg origin. A CDN URL that appears in no file (read from the database or an env value) is not seen: list its origin under `csp: script_src` (and `connect_src` for fetch/import) here.
