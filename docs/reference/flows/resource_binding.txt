A :param route resource cannot be replaced by query or POST form values. A query or form value whose name is a path parameter must equal the path value (every repeat included), else the request answers 400 `Conflicting flow path parameter` before any step runs and before the auth and CSRF gates, so an anonymous or cross-site request with a conflicting value gets this 400 rather than 401/403. A JSON body value of that name is ignored: the path value wins, so a client that echoes a stored row (`{"id": null}`, a large numeric id) keeps working. A `verify:` flow binds no query field, so its query is not checked (a bad signature stays 401); its form fields are checked after verification, except the hmac_sha256_path_bearer signed parameter, which a form field never replaces. Use resource-specific names such as patientId or recordId: session identity keys (user, user_id, user_role, user_email, user_group_id, _group_id, _group_key) are reserved and later bound from authentication, outside this resource-binding contract. Raw {param} binding is not covered.
