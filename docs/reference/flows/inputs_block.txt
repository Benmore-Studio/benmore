Optional `inputs:` on on.request declares the flow's input signature - keyed by name, each `{type, required?, label?, help?, values?(enum), default?, min?/max?(number)}`. Types: text|textarea|number|bool|date|enum|email. Declared values are validated before steps or async enqueue: a missing required input or a value its type, values or min/max refuse answers 422. An optional input the caller omits (or sends as null) takes its `default:`, bound like a sent value - `${{ params.hours }}`, `:hours` and an async job's payload all see it, as a number, boolean or text per its YAML type. A default never satisfies `required: true`. The write gate and `benmore check` refuse a default that the input's type, values or min/max would refuse from a caller. It (a) types the bm.flows.<name>() body and (b) lets the `FlowForm` component derive an input form - see api({at:'components'}). Example: `inputs:\n  message: { type: text, required: true }\n  tier: { type: enum, values: [standard, rush], default: standard }`. Each field, the checks, the refusal bodies and a whole flow: `inputs`.
