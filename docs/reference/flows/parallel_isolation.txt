Parallel branches receive the same input snapshot, each with its own parameters, outputs and request/secret taint. Siblings cannot consume each other's in-flight results; put dependencies in sequential steps. After all branches succeed, outputs merge in declaration order (a later declared writer wins a shared name), with request/secret taint retained. A failed block discards its outputs while preserving any already-durable external or database effects; parallel is not a transaction. Respond, redirect, serve_file and request-body parse steps must be moved before or after the block, including inside nested branches; validation and runtime reject them before any sibling executes. `retry`, `retry_delay` and `on_error` on a direct child of the block are ignored (step_keys → accepted_but_ignored); put `on_error:` on the parallel block.
