A request field named like one of the flow's step ids is readable only as `${{ params.<name> }}`: a bare `{{name}}`, `${{ name }}`, `${{ name.x }}` or `:name` reads the STEP (its output, or nothing before it has run), so `- id: challenge` with `if: ${{ challenge }}` never sees the request's challenge. `${{ params.<id> }}` reads only the request field: when the request did not send it, it is missing (use `| default:`), never the step's output. The same holds for a `run: set` key and a for_each loop variable: `params.page` after `set: { page: ... }` and `params.row` inside `for_each ... as: row` are the request's fields or missing, never the set's value or the current row; read those as `${{ page }}` / `${{ row }}`. A value an enqueue step passes under such a name still reads as `params.<name>`. Identity values (`params.user_id`, `params.user`, `params.user_role`, `params.user_email`, `params.user_group_id`, `params._group_id`, `params._group_key`) are the exception: they come from the session, never the request. An unnamed parse step's output also stays readable as `params.body` / `params.form`. Name steps differently from request fields. The post-write check and `benmore check` warn (not refuse) when a step id equals an on.request.inputs name or a bare ref/bind in that step or an earlier one; a bare ref after the step reads the step's output and is not flagged.
