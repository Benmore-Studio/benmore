on.request.contract declares private OpenAPI schemas: request_body is an optional JSON Schema (required body when declared unless request_body_required: false); request_body_required is boolean and requires a body declaration; request_body_media_types is a nonempty unique list of application/json and/or application/x-www-form-urlencoded (default application/json; form requires POST and an object body), query is an optional object schema whose properties become query parameters, headers is an optional closed object schema whose string properties become header parameters, and responses is a required status-to-schema map with explicit quoted 200-599 keys, excluding bodyless 204, 205 and 304, and at least one 2xx. A content wrapper has only its content key and one or two media entries. Each response value is a JSON schema shorthand for application/json, or a content wrapper such as {content: {application/json: {type: object, properties: {}, additionalProperties: false}, text/plain: {type: string}}}. Only application/json and text/plain are allowed; text/plain requires type: string, and content cannot be mixed with schema keys. No response media or form encoding is inferred. Example: contract: {query: {type: object, properties: {limit: {type: integer}}, additionalProperties: false}, responses: {'200': {type: array, items: {type: string}}}}. Contract-bearing routes must be synchronous, use GET, POST, PUT, PATCH, DELETE or OPTIONS, and have an exact path with :name parameters (no braces, catchalls or trailing slash). HEAD is refused and GET cannot declare request_body. A flow with request signature verification (on.request.verify) cannot declare a contract; such declarations are refused. Path :name parameters are derived as required strings. Every object must declare additionalProperties: false or a typed schema; query and headers require additionalProperties: false. Headers example: headers: {type: object, properties: {Idempotency-Key: {type: string}}, required: [Idempotency-Key], additionalProperties: false}. Header schemas require type: string and may also use pattern, minLength and maxLength (no enum, defaults, examples or metadata), at most 32 RFC-token names of 1-64 characters, and no case-insensitive duplicates. required names must match property spelling exactly. Authorization, Cookie, Set-Cookie, Host, Connection, Content-Length, Content-Type and Accept are reserved and refused. Header declarations describe required parameters but do not enforce headers at runtime. Supported schema keywords are type (one of object, array, string, number, integer, boolean, null), properties, required, items, enum, anyOf and additionalProperties (false or a typed schema), plus type-specific pattern/minLength/maxLength for strings, minItems/maxItems for arrays and minimum/maximum for numbers. Count bounds are integers from 0 to 1000000; numeric bounds must be finite, and minimum bounds cannot exceed maximum bounds. pattern is an ECMAScript expression of at most 512 bytes. Public auth: none or optional routes without role/permission gates export security: []. References, examples/defaults, free metadata, unknown keywords and unconstrained object extras are refused. These declarations describe the contract; they do not validate requests/responses at runtime or change generated SDK types. Keep runtime validation and authorization in the flow. Custom flow metadata appears only in the full developer/admin OpenAPI audience, never ordinary caller docs. A deployed contract the write gate would refuse is logged (WARNING) at load and omitted; the flow itself still loads. See api(at:'machine-discovery').
