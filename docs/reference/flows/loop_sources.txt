for_each runs once per element of a list of objects or of scalars (`for_each: ${{ params.emails }}` over `["a@example.com"]` runs once); a scalar element is the loop variable itself (`${{ item }}`). It resolves native arrays from nested compute outputs and request objects, including indexed paths such as steps.plan.outputs.groups[0].lines. A compute result need not put its array at the top level. Direct context keys keep precedence; empty, null or missing sources still run zero iterations (an empty list, JSON text `[]`, empty text, null, an empty object or a reference with no value). JSON text of an array is iterated, decoded the way a respond body decodes it, so `for_each: ${{ steps.agg.outputs.first.items }}` over a `json_group_array()` column runs once per element; text the caller sent is never decoded, so send a list as a JSON array in a JSON body. A non-empty source that is not a list (other text, an object, a number, a boolean) fails the step with `for_each: the source ${{ params.lines }} is an object, not a list, ...` and reason `the loop's source is not a list`, in request, async, enqueued, scheduled and data-event flows alike. For an API envelope name the list (`${{ steps.call.outputs.json.results }}`). A loop iterates at most 10,000 items: a longer source fails the step before the first iteration (`for_each: 10001 items is over the 10000 a loop may iterate; page the source (LIMIT/OFFSET) or enqueue the work in batches`). Assert expected business row counts when an empty result would be invalid. Loop variables retain request/secret taint and reached-step shadowing.
