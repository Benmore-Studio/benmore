INSERT INTO ... SELECT ... ON CONFLICT accepts an existing outer WHERE predicate; WHERE true is only a separator fallback when SQLite could mistake ON for a join constraint. Other SELECT-closing clauses such as ORDER BY or LIMIT also disambiguate the statement. A WHERE inside a subquery, quoted value or comment does not separate the outer SELECT. The write gate and benmore check share this syntax hint, and automatic normalization preserves already-disambiguated statements. This is not complete SQL validation; bind request values and verify actual persisted effects. The same check refuses `RAISE()` in a flow SQL step, which works only inside a SQLite trigger: stop a flow with an `if:` step and a `run: respond`.
