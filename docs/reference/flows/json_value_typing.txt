How a `${{ }}` value is typed in a JSON body (respond `json:`, a `run: api` `json:` map, list or reference, a `run: webhook` `body:`/payload, a broadcast payload). A value that is already structure (a step's rows or object, a compute result, an object or array a JSON request body sent as JSON) is written as that structure. A string that is JSON text of an object or array is decoded, so a `json_group_array()` / `json_object()` column or a JSON-text step output arrives as an array or object, unless it is request text: a string the caller sent (a query, form or path field, a JSON-body string, a parsed body or header), or a `run: set` value or loop variable built from one. Request text stays the string it is, so a form field `a={"admin":true}` is the string `{"admin":true}` in the response and in an outbound body, never an object, so a caller cannot inject NoSQL operator objects or extra keys upstream. A step's output is not request text even when the step read request input (`SELECT json_group_array(tag) ... WHERE owner = :owner` still decodes), and neither are loop variables over it or data-event rows. A string template that substitutes request text is decoded only when you wrote it as a JSON document (`'{"q": "${{ params.q }}"}'`), and then value by value, so a value can't close a string or add keys; any other such template stays a string. `"true"` and `"123"` are not decoded in a `json:` map; in a value position of a JSON text body a number, true/false or null is written as one. Validate any object or array a JSON request body sends before you forward it.
