A whole-value boolean reference in run: sql with.params (for example passed: '${{ steps.grade.outputs.passed }}') binds SQLite's 1/0 representation. BOOLEAN columns then return true/false and predicates such as passed=0 work, matching direct SQL expression binding. The same holds for a boolean computed in the value, in with.params and inline in the query alike: a comparison or `!` (`big: '${{ params.n > 3 }}'`), an `&&`/`||` expression whose result is a boolean, and a boolean passed through `default:` (`${{ params.rush | default:'0' }}`) bind 1/0, so `CASE WHEN :rush` is true when the request sent true. An expression's other results bind as their own type (a number as a number, null as NULL). Literal or resolved strings, embedded text and other pipes retain text semantics; use the json pipe when text 'true'/'false' is intended. A `default:` fallback is the literal text you write, so for SQL write it as `default:'0'`/`default:'1'`, not `default:false`. A raw `:name` bound straight from a JSON request boolean binds its text ('true'/'false'): route it through with.params (`rush: '${{ params.rush }}'`).
