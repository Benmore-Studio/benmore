A `steps.<id>` reference whose id no step of the flow has is refused when the file is written and by `benmore check`, wherever it sits (if:, for_each, success_when, a with: value, params, a query's or respond body's `${{ }}`). The message names the step, the id, the closest id and the flow's ids: reads `steps.lookpu`, but no step in this flow has id "lookpu". Did you mean `steps.lookup`? The flow's step ids are deny_paid, lookup, v. At run time such a reference reads as empty: an if: on it is always false, so a deny guard with a misspelled id never fires, and a for_each over it runs zero times. Ids are collected from the whole flow first, at any depth (if/else branches, for_each and parallel bodies, on_error handlers), so a reference to a step later in the file (a loop's next iteration, an on_error handler reading the failed step) is accepted. Each job of a file is its own flow, so an id from another job is refused. Text outside `${{ }}` (SQL such as `FROM steps s`) and quoted text are not references. An app already running such a flow keeps loading it.
