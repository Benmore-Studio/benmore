A synchronous HTTP respond ends the flow, whether or not it has a body: a refusal written as `with: { status: 403 }` stops the run there, and no later step runs. File writes and benmore check refuse steps after an unconditional respond in the same sequence, including nested branches and error handlers. Move required work before the response. An inline if-gated response can still have reachable following steps. A deployed file with such steps keeps loading. In async and scheduled flows there is no HTTP response to write, so a respond step does nothing.
