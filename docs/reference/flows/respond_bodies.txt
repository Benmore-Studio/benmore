A `run: respond` sends one body, written as `body:` or as `json:`, and sends it as written. With both set the step still sends one: a `body:` written as text, a map or a list is the one sent, and the `json:` is not; push and benmore check warn and name the one that is sent, so write one of the two. Beside a `json:`, a `body:` that is empty or only whitespace is not a body, and the JSON is sent with no warning: `with: { status: 403, body: "", json: { error: forbidden } }` answers 403 with `{"error":"forbidden"}`. With no `json:`, `body: ""` answers the status with an empty body. A `body:` or `json:` written as an unquoted date or timestamp (`body: 2026-11-12`) is sent as the text written, typed exactly like the same text in quotes (text/plain unless `content_type:` declares another type). A `body:` or `json:` written as a number or boolean is that JSON value, not the text typed: `body: 1.50` answers `1.5` as application/json. Quote a value meant as text (`body: "1.50"`), and write a value meant as JSON under `json:`; push and benmore check warn on a `body:` written as a number or boolean, not on one under `json:`. A number with no JSON form (`.nan`, `.inf`) is not sent: quote it. A respond with no body at all (`with: { status: 204 }`) is a complete answer: see step_types.
