A number reaching text is written in full, the way JSON writes it. A number from a JSON request body, an inbound webhook body, a run: api response, a compute result or an async job payload is written as 1234567, never as 1.234567e+06 (which SQLite's CAST(x AS INTEGER) would read as 1): :name params, with.params templates, quoted '{{x}}' SQL values, URLs, headers, text bodies, conditions, pipes, hook and notification templates and SSR {{x}} all write 1234567, and a fraction keeps its digits (1234567.5). A bare {{x}} in SQL binds a whole number as INTEGER. Only magnitudes at or above 1e21 or below 1e-6 keep an exponent, as in JSON. An integer beyond ±2^53 in a flow request body, a `run: api` response or an async job payload (a 64-bit Discord/Twitter id) keeps every digit, as it does in an auto-CRUD body.
