`on.request.auth: optional` (flows only) admits every caller. A signed-in caller gets exactly what `auth: required` binds (`${{ user.* }}`, `:user_id`, `user_group_id`, the tenant key `:_group_id`); an anonymous caller gets the same names as null (`${{ user.id }}` renders empty, binds SQL NULL and is falsy in `if:`), so one route serves both (an Add-to-Slack link that remembers who installed it when they are signed in). Request fields named user/user_id/... are never identity. Where the scoped-credential rule is enforced (`permissions`), a scoped API token or session counts as anonymous here; where it is not, it is bound as its user and the app log notes it. CSRF applies whenever a session cookie is sent, and a response may not be shared-cached (Cache-Control public/s-maxage is refused as on signed-in flows). `role:`/`permissions:` still require sign-in. A public flow (`auth: none`) keeps binding only the flat user_id/user_email of a signed-in caller.
