`${{ steps.<id>.outputs.<name> }}` reads column <name> of a run: sql step's first row; a name the query does not return resolves to nothing: in a comparison it is empty against a literal (missing_values). Push and benmore check read the result columns from the step's text (an explicit SELECT or RETURNING list, aliases included; a write without RETURNING outputs only rows_affected) and refuse an if: that reads any other name, since such a guard never sees the value it tests (`if: ${{ steps.me.outputs.count }} == 0` over `SELECT member_role ...` never matches). Other references are warnings. Steps whose columns the text does not name (`*`, an unaliased expression, sql_dynamic) are not checked, and an app already running such a flow keeps loading it. Select the column (`SELECT COUNT(*) AS n`), or test for rows with `${{ steps.<id>.outputs.rows }}`.
