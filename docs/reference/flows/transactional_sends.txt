`run: email`, `run: sms` and `run: webhook` inside a `transaction: true` flow (HTTP or scheduled) send at once, so a later failing step rolls the rows back after the message has gone. Queue the send with `run: enqueue` (written inside the transaction, runs after COMMIT), or send from a separate flow. A write of the flow file and `benmore check` answer with a warning for each such step, at any nesting depth, and the app logs a WARNING per step when it loads the file; the file still pushes and deploys. A step under `on_error` runs after the rollback and is not reported. `run: api` is not reported either (later steps read its outputs); a failing step after an API write does not undo the call.
