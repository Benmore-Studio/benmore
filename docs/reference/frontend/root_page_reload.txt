A successful hot reload refreshes root-level server-rendered HTML pages, with or without mcp.yaml: added routes become available, deleted routes disappear, and replacement page gates, partials and discovered auth paths take effect. Root pages coexist with static/ pages; an unmatched HTML navigation can still reach the static SPA fallback. A rejected reload keeps the published page set. An app with a reviewed mcp.yaml serves the source captured at its last load or reload. A source-write acknowledgement proves persistence and queues the reload; verify the actual route and its access behavior once the reload has happened. See api(at:recovery) for restart/reload verification.
