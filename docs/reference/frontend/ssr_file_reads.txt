Every source file the server renders, mails or serves verbatim must resolve inside the app directory: root pages (`*.html`), `layouts/<name>.html`, `partials/kit.html`, `head.html`, `theme.css`, flow and hook email templates (`emails/<name>.html`), and the `static/sitemap.xml`, `robots.txt`, `llms.txt` and `llms-full.txt` overrides. A symlink works only when its target is relative and stays inside the app directory (an absolute target is refused even when it points inside), and a `layout=` value or email `template:` with `..` resolves inside the app directory or is not found. A refused file behaves as a missing one: the page renders without the layout, kit or head, the generated sitemap/robots/llms is served, a flow answers `email step: template ... not found`, a hook email sends its literal template text. A refused root page stops the app from loading or reloading (`pages: read <file>: ... path escapes from parent`): it is never treated as a removed page. Includes and partials follow the same rule (see partials). Share files between apps by copying them in, not by linking out.
