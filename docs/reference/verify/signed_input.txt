No verifier signs the URL query string (body recipes and the stripe/github/shopify/slack forms sign the body, the shared-secret header forms sign nothing, `hmac_sha256_path_bearer` signs one path segment), so a flow with `verify:` (string or map form) binds nothing from the query: a query field is not a param, `:name` bind or `{{name}}` value, and `run: parse` of a form body reads only the body's fields. The route's own path parameters still bind. With `hmac_sha256_path_bearer` the signed `path_param` segment is never replaced by a query or form field of the same name (a caller holding the token for `/hook/a` cannot act on `b` with `?handle=b` or a form field `handle=b`). Send every value the flow reads in the signed body, or put it in the route path.
