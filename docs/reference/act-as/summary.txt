Admin step-in. Lets a platform-admin session opt INTO per-tenant scoping for the duration of step-in - every read filters to the acting-as group and every write auto-injects its group_key, exactly as for an ordinary member of that group. The admin's Role stays `admin` so admin-only surfaces (the /_admin panel, /api/_audit and the other admin management endpoints) remain reachable; only the data-scoping rule changes. Hard server-side boundary, not a client-side UI trick - even a determined admin who curls the API while stepped in sees only that tenant's rows. Which key answers which who-may-see-this-row question: api({at:'access.which_topic'}).
