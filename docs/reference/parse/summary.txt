`run: parse` reads one explicit request source into `steps.<id>.outputs`. The default `source: body` parses urlencoded form fields (`application/x-www-form-urlencoded`), or decodes JSON (1 MiB cap; invalid JSON fails; a larger JSON body, or a form over the app's body cap, fails the flow with 413 and the limit); JSON object keys and Stripe-style `data.object` are flattened. Fields of a multipart/form-data body are not read, by this step or as automatic `:name` / `${{ params.<key> }}` bindings. `source: headers` exposes the inbound request headers as a map from canonical header names to arrays of values, preserving repeats; it never reads same-named body fields. Header values are untrusted request input and remain tainted for the `sql_dynamic` guard. Validate cardinality before using security-sensitive headers, and never return the whole map because it can contain credentials. It does not parse XML, CSV or HTML, or an upstream `run: api` response.
