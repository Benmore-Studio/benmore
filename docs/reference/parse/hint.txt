Top-level JSON body keys already bind as `:name` / `${{ params.<key> }}` without a parse step; use `run: parse` with `with: { source: headers }` for inbound headers or for form bodies/nested JSON paths. Header names are canonicalized and values stay arrays so duplicate security-sensitive headers can be refused; body fields cannot spoof them. Strict HTTP routes opt in with `on.request.strict_json: true`: application/json object only, at most 32 KiB, valid UTF-8, no duplicate keys at any depth, malformed/trailing JSON refused before steps. Parsed values are request input for the sql_dynamic taint guard. A `run: api` step exposes `outputs.status`, `outputs.headers`, `outputs.body` (raw text) and `outputs.json` (when the response is JSON); non-JSON text such as XML has no built-in parser - pass `outputs.body` to a `run: compute` module.
