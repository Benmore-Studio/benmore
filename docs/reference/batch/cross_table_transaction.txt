POST /api/_transaction {operations:[{table,action:'insert'|'update'|'delete',data?,id?,ref?,ref_op?}]}. Each operation runs access/scope/membership checks, validators and before-hooks on the active transaction; update operations use the same canonical mutation pipeline as native PATCH, including optimistic concurrency, SQL-only after-hooks, authoritative readback and transactional audit/job intents. A failure rolls back every operation. Ref IDs confer no authority. Parent founder-membership creation is atomic. External network delivery remains post-commit; grant-aware retries/recovery are not provided, so connector writes to tables requiring them remain gated. The private B2 revision foundation is separate and opt-in: explicit administrator bootstrap creates incarnation-bound row revisions and retained tombstones in one transaction, while per-capability verification is read-only and refuses missing/changed sidecars or triggers, unsupported tables, and alternate UNIQUE indexes. It is not startup- or MCP-write-wired; independent enrollment and restore-epoch/incarnation binding remain required before approved writes.
