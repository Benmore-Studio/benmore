A `.yaml`/`.yml` file the framework has no rules of its own for (a test file, schema.yaml, a data file the app keeps) is still parsed on every write: one that is not valid YAML is refused by the write gate, `benmore push` and `benmore check` with `yaml syntax in <file>:` and the parser's message, which names the line. The usual causes: indentation that changes inside a block, a tab used for indentation, a `[` or `{` that is not closed, a quote that is not closed, and an unquoted value that starts with `*`, `@`, `%` or a backtick or that holds `: `. Fix the line the message names and write the whole file again. A test file (directly under tests/) that is not valid YAML is also a failed `load` result of `benmore test`, and its refusal points at `test_file_load`. A file over the size limits is refused before it is parsed: see `yaml_resource_limits`.
