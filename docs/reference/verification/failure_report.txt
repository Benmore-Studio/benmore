A verify report names the instance it checked (`environment`: always dev), marks a check the profile includes but that did not run as `not_run` with a `reason` (YAML tests and journeys after a failed acceptance contract, no journeys, --quick without smoke journeys), and lists `next_steps`: per failed check the command or evidence file to read next (sync → `benmore sync-status <dir> --env dev --json`, yaml_tests → tests.json, which is written also when the tests could not start (it then holds the failed `setup` step, `copy source` or `load app`, with the reason), journeys → journey-*.json or `benmore qa draft`, release_safety → `benmore status`/`benmore doctor`). `ok` is true when `failures` is empty; text output prints the same as `NOT RUN:` and `Next:` lines. The sync check is the comparison `benmore sync-status <dir> --env dev` prints: it fails exactly when that command exits 1 (drift) or 2 (conflict), so a migration the instance wrote itself (`instance_migration`) and workspace files that are never uploaded (`kept_local`) do not fail it. The `manifest` and `source_snapshot` checks hash the files deploy uploads; `kept_local` files are not part of that proof.
