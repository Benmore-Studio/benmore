A test file under tests/ maps each test name to a test case. A test case takes `steps` (a list, at least one step), `setup` (a list of `{sql: <statement>}` entries run before the steps; `{{user_id}}` is the test user's id), `as_user` (an email: the test signs in as that user), `as_role` (that user's role, `user` unless set), `users` (further accounts to create before `setup` runs, each entry an email, for role `user`, or `{email, role}`; a step acts as one through `set_auth`) and `anon` (`true`: no session and no CSRF token). A step takes exactly one action: `api` (`"METHOD /path"`), `get` or `post` (a path), `sql` (a statement), `flush` (`jobs`, `retention`, `scheduled` or `errors`) or `set_auth` (who the steps after it act as: `bob_token`, the saved session token of the test account bob@example.com, a token a step saved, written `{{name}}`, or `none`; api(at:"verification.test_variables")). A request step (`api`, `get`, `post`) may take one body (`data`: form fields, `json`: an object, `json_array`: a list, `ndjson`: a list of objects, `files`: `{field: {name, content}}`), `bearer: true`, `save` (`{name: <response field>}`, read back as `{{name}}` in later steps, their `expect` included; on a `sql` step the columns of the first row; an entry that saves nothing fails the step) and `expect`. On a request step `expect` takes `status`, `status_in`, `redirect`, `contains` and `not_contains` (text or a list of text), `json` (`{path: value}`), `json_length` (the response must be a JSON array of that length), `headers` and `max_duration` (`100ms`, `2s`); on a `sql` step it takes `rows`; `flush` and `set_auth` steps take no `expect`. A request step whose `expect` names neither `status` nor `status_in`, or that has no `expect`, fails on a status of 400 or above and passes its status check otherwise; a `sql` step with no `expect` passes when its statement runs. `benmore test` fails a test it cannot read in full, without running any of its steps, in every mode (the default, `--app` and `--framework`): a key that is not one of the above at its level (`expects:` for `expect:`, `step:` for `steps:`, `contain:` under `expect`), no steps, a step with no action or with more than one, an `expect` key the step's action does not check (`contains` on a `sql` step, `rows` on a request step, `status` beside `status_in`, which is the one checked), a `contains` or `not_contains` value that is not text (quote a number), a `max_duration` that is not a duration, a `setup` entry without `sql`, or a `users` entry that is not an email or a mapping, has no `email`, or holds a key other than `email` and `role`. The result is `<file>` / `<test>`, failed, with a message that starts `not run:` and names the file, the line, the key and the nearest key the runner reads, then a `docs: api(at:"verification.test_keys")` line; the other tests of the file still run, the summary is failed and the exit status is 1. `benmore check` and a write of the file report the same reasons as a warning naming each test; the write is not refused.
