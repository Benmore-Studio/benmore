`benmore test` fails the run on a file under tests/ that it cannot load, in every mode (the default, `--app` and `--framework`): the result is `tests/<file>` / `load` with the reason and a `docs: api(at:"verification.test_file_load")` line, the summary is failed and the exit status is 1. A file that is not valid YAML is reported once, as this `load` result. A file is not loaded when it is not valid YAML, does not decode into test cases (a list under `json:` or `data:`, which take a mapping; send a list body with `json_array:`), is empty or holds only comments, has a top level that is not a mapping of test name to test case, or holds a second YAML document after `---`. The other files' tests still run. `benmore check` and a write of the file report the same reason as a warning; the write is not refused. Only `.yaml`/`.yml` files directly under tests/ are test files: tests/journeys/ and other file types are left alone.
