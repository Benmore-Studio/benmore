`benmore test` runs on a disposable copy of the app's source (in the system temp directory, removed afterwards) and never writes the workspace: its data.db, uploads/ and .benmore/ stay as they were. The copy leaves out .benmore/, .git/, node_modules/, uploads/, database files (data.db*, *.db, *.sqlite), .env*, secrets.yaml, *.key and *.pem, and keeps the app's env.yaml, which the app reads its configuration from. A workspace that `benmore deploy` or `benmore pull` linked (it has a .benmore/ directory) is tested like any other directory. A hosted app instance (a directory with .benmore/server-secret, which the platform writes into each instance it serves) is refused. A run that cannot reach the tests (that refusal, a failed copy, an app that does not load) exits 1 and prints a failed `setup` result naming the step and a `SUMMARY` entry, so `--json` output shows the tests did not run.
