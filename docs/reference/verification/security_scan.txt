`benmore security-scan <app> [--env dev|prod]` answers the instance's latest stored security scan: `score` (the passed checks as a percentage), `total`, `passed`, `warnings`, `failed`, `scanned_at` and `checks`, each with `tier`, `category`, `name`, `status` (pass, warn or fail) and `detail`, plus `request`, `response`, `expected`, `remediation` and `owasp_id` where they apply. Before the first scan it answers `score: 0`, no checks and a `note`. `--run` (MCP run_security_scan) runs a scan first and answers its result: checks of the app's source, then live requests to the selected instance (response headers, sign-in and cookie checks, injection and access probes). A scan started from the CLI never sends the one probe that could delete a row. With no `--env` and no pin the target is prod once the app has a prod instance, else dev: pass `--env dev` to probe the dev instance. Editor access.
