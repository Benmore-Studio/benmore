`benmore test` answers a held account as the server does: a credential of an account that must enroll MFA (auth.require_mfa_for_roles, the default under compliance: hipaa; api(at:"mfa") -> existing_credentials) gets 403 `mfa_enrollment_required` with `redirect` from /api/ paths and Bearer steps and a 303 to the setup page on a page, and a session of an account that must replace a temporary password (api(at:"auth") -> required_password_change) gets 403 `password_change_required` or a 303 to /auth/change-password. Test users of a listed role are given a factor, so only a test that removes it (a `sql:` step setting `totp_secret = NULL`) or sets `password_change_required = 1` meets a gate. Not applied in a test run: rate limiting (429), the request-body cap (413 over 10 MB or MAX_REQUEST_BODY_BYTES), CORS (a step cannot send an Origin header), the DEMO_PASSWORD visitor gate, request logging and metrics, and the 500 page for a panicking handler (the step fails with a request error). A step's SQL that changes an audit table of a compliance: hipaa app is refused (`<table> is append-only`) and the failure says to move the statement to `setup:`, whose SQL is exempt.
