The generated framework tests (`benmore test --framework`, and the generated half of `benmore verify`) sign in as a plain user (`_test_user@benmore.test`, role user, no tenant) and assert what the app declares for it. A table whose access mode closes an operation (`off`, `admin`, `role:`/`perm:` it lacks) is asserted to answer 404 `no API route matches this path` (a create, update or delete it refuses on a table the user may read: 403 `access rules do not let you`); one whose `roles:` scopes do not name it is asserted to answer 403 `scope denied`; success journeys are generated only where the create is allowed, and each later step (read back, PATCH, DELETE) asserts that operation's refusal when it is closed. A create first creates the parent row of every required foreign key (and the parent whose membership a `member-of:` write needs) through the API and references its new id; unique columns get values no other generated row shares, and a table limited to one row per account gets a test identity of its own. A social-only app (`auth.oauth_only`) has the password token exchange asserted refused; an `auth.domain` rule is exercised with an identity in the domain plus a refusal for one outside it. With `features.admin`/`features.docs` off, an app page that answers `/_admin` or `/docs` (an HTML app's index fallback) is expected instead of a 404. The generated `health_fast` test asserts that an anonymous `GET /health` answers 200 within 10 ms. It sends up to five requests and passes at the first one that answers within 10 ms, so a busy moment on the machine running the tests does not fail it; when all five take longer it fails and lists the time of each request. A `max_duration` written in a test file is checked against the step's one request. A journey the generator cannot build (a required parent the plain user cannot create, a required column no client may set, a tenant-keyed table) is reported as `SKIP` with the reason and does not fail the run.
