Never list an encrypted column (encrypted.yaml / app.yaml encrypted:) in @@fulltext: the index is built from plaintext, the encryption trigger then rewrites the column, the index desyncs and every INSERT fails ("database disk image is malformed") - and the index would hold the plaintext. Write-time validation and `benmore check` refuse the combination. Index only non-sensitive columns; use `blind_index:` for exact-match lookup on encrypted data.
