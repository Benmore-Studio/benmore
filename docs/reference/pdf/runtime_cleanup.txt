Each render (GET /pdf/<page>, and a connector PDF artifact) runs Chrome with a private home, cache, config and data directory and a disposable browser profile inside that render's temporary directory; it uses neither the server account's browser profile nor its password store or keychain. The directory is removed when the render ends: success, start failure, renderer failure or timeout. On macOS Chrome keeps the account's HOME; the profile and the other directories stay private. This contains the browser's helper caches, not arbitrary filesystem access; it does not remove residue from older renders, and it does not make rendering work on a host whose browser cannot start (see requirements and failed_renders).
