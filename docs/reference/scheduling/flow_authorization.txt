kind:flow requires a real login outside act-as/support impersonation at creation. The task stores an owner/tenant/permission delegation, never a login credential; logout and session expiry do not cancel it. At execution the owner must still be active and hold the delegated roles and a live tenant membership under the same rules as a request (soft-deleted or groups.active_field-inactive rows never count; an email-keyed row needs a verified or grandfathered address; an id-keyed user_field matches the user id); otherwise the task is held as blocked. Added roles cannot expand the stored delegation; scopes intersect current grants. HTTP flows retain their normal role gates; internal/cron/event flows require a global administrator. Async definitions execute inline in the scheduler. Signature-verifier and account-erasure flows cannot be delegated. Execution uses the HTTP flow pipeline with trusted identity and input taint. Put any route path parameters in body. Rate limiting before execution defers the task; execution failures become failed and do not generate a success notification.
