A transition's `role:` (each listed role, see role_lists) passes for a platform admin, for the _benmore_users.role hierarchy, for an exact role match on the caller's live membership row in their CURRENT effective tenant, or for a role grant in _benmore_user_roles counted as a `role:` access rule on the workflow's table counts it: a grant for the caller's current tenant only when the table carries the groups key, otherwise only a global grant (group_id NULL); expired grants never count. Membership authorization reads groups.role_field when configured; only apps without that setting use the membership table's `role` column. A missing, NULL or empty configured field never falls back to that `role` column. Another tenant's role, a missing current tenant, and inactive or soft-deleted membership grant no membership authority; email-keyed membership requires a verified address. Approved MCP commands recheck the same configured field inside their commit transaction. SSR user.app_role, user_app_role and {{#role}} sections use this configured per-tenant role too.
