A transition's `role:` is one role or an any-of list, like an access `role:a,b` mode: `role: "owner, manager"`, `role: owner,manager` or `role: [owner, manager]` (flow or block YAML list). The caller passes when it holds any listed role, each matched as transition_roles describes. A caller who holds none of them gets 403 `one of the roles 'owner', 'manager' required for this transition` (one role: `role 'admin' required for this transition`), GET /transitions reports the list as `role: "owner,manager"`, and approved MCP commands check the same list. A `role:` that names no role (`role: ","`) is refused at push and by `benmore check` (a deployed one admits only a platform admin); `role: []`, a map or a nested list fails to load. Push and `benmore check` warn about a listed name no other part of the app names (app.yaml roles:, groups.bootstrap.founding_role, an access role:/owner_or_role: mode, a flow role:) and that is not built in (admin, manager, editor, user): usually a typo, which nobody holds. An in-tenant role that exists only as data in the membership table's role field also warns; ignore it then.
