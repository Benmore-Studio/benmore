A create (single, batch, ingest, `/api/_transaction`, `/api/_groups/create`) always writes the workflow's `initial` state into the state column, whether the caller sent another value, an explicit JSON `null` or nothing. So do the rows the framework inserts itself: bulk import Mode A (the file cannot name the state column), the founding membership row of `/api/_groups/create` and the member-of founder auto-join, when the table they write has a workflow (a column those inserts already write, such as the founding role, keeps its value). A workflow with no `initial:` drops a submitted value so the column default applies. An approved MCP command that inserts a row whose state is not `initial` (including NULL) is refused. The write gate and `benmore check` refuse a state column whose `@default` differs from `initial:` (a flow, hook or SQL insert that leaves the column out takes the default).
