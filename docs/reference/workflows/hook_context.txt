An on_transition entry sees the row after the transition (every column, the state column set to the new state), `{{old_<column>}}` for each column's value before it, and the caller's session context like every hooks.yaml hook: `{{user_id}}`, `{{user_email}}`, `{{user_role}}`, `{{user_roles}}` and `{{user_group_id}}` are the user who made the transition, and they replace the row's own user_id. To reach the row's owner use `{{old_user_id}}` (a transition never changes user_id); any other owner column (`{{client_id}}`) is read as is. A timeout transition has no caller: user_id is then the row's own column and the other session keys are unset, so a hook that must reach the owner on both paths uses `{{old_user_id}}`: timeout transitions carry old_<column> for every column too, so it resolves on both paths.
