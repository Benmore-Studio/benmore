`table:` and `field:` may be spelled in any case (SQLite folds identifiers); they are matched to the schema's spelling, so every guard that compares names (a create may start only in `initial`, PATCH cannot write the state column, the transition route) applies to the real column: `field: Status` guards the column `status`. The transition routes are registered under the schema's table spelling and under the spelling workflows.yaml used, and `<transitions table=>` matches case-insensitively. A `field:` that is not a column of the table is refused at write time and by `benmore check`; a deployed file that names one still loads with a warning and enforces nothing.
