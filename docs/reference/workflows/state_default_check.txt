The check that the state column's default equals `initial:` (create_null_state) reads the default as SQLite applies it. In a schema.sql app `DEFAULT 'draft'`, `DEFAULT "draft"`, `DEFAULT draft` and `DEFAULT ('draft')` are the same text and all pass for `initial: draft`; a column with no default or with `DEFAULT NULL` passes too (both store NULL, and every create writes `initial`). A refusal names the fix in the app's own schema file: `@default("draft")` in schema.prisma, `DEFAULT 'draft'` in schema.sql. The write gate, `benmore check` and the warning logged at load use the same check.
