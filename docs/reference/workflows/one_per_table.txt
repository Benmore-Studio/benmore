A table has one workflow. Two workflows that name the same table are refused when workflows.yaml is written, by `benmore check`, and at startup and reload (`workflows "fulfilment" and "payment" both name table "orders"`); table names compare as SQLite compares them, so `Orders` and `orders` are one table. POST /api/<table>/{id}/transition takes only `to` and GET .../transitions answers one `current`, so a table's routes move one state column. A rejected reload keeps the previous workflows, handler and background workers. For a second state on the same record, give it its own table with its own workflow (a row that points at this one).
