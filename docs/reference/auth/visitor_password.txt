`benmore demo-password <app> <password> [--env dev|prod]` (MCP set_demo_password) puts a visitor password in front of an app, for sharing a preview without making it public; `benmore demo-password <app> --remove [--env dev|prod]` takes it away. While it is set, a visitor gets a password page before any page of the app, and /api/* answers 401 `{"error":"visitor password required","login":"/_demo/login"}` without the visitor's cookie, except to a request with a valid bearer credential and to flows that declare `verify:` (signed inbound webhooks); /static/, /_internal/, /auth/, /health, /robots.txt, /favicon.ico and /sw.js stay open. It is not a sign-in: the app's own auth applies behind it. The password (at least 4 characters) is stored as the env value DEMO_PASSWORD in the scope `--env` names; with no flag and no `benmore use` pin it is shared by both instances. Setting and removing take effect on the running instances and need editor access.
