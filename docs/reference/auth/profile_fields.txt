PATCH /api/_auth/profile writes only self-service columns: first_name, last_name, name, display_name, avatar, avatar_url, bio, timezone, locale, every auth.signup_fields column, and the comma-separated app.yaml auth.profile_fields list (e.g. `profile_fields: "pronouns,company"`). Any other existing _benmore_users column returns 403 {error, fields, hint} before anything is written, unless the request only echoes its current value (GET→edit→PATCH round-trips keep working). Columns used for authorization - plan, tier, credits, tenant bindings - must be set by a server-side flow or admin tool, never listed in profile_fields. Protected columns (id, role, verified, password_hash, deactivated_at, password_change_required) and secret-shaped names are never writable here, and neither is any column a public signup refuses: account state (email_grandfathered, last_login_at, deleted_at, user_id, created_at, updated_at) and the groups: key, role_field and active_field columns, even when signup_fields or profile_fields lists them (403 like any other undeclared column).
