Boolean auth keys (require_verified, verify_email, otp, oauth_only, read_audit_sync, passkeys, signup, password_reset, api_tokens) take true/false, and yes/no, on/off, 1/0 mean the same. Any other value is refused at write time. `auth.identifier` takes `email` (the default), `username` or `phone`, in any letter case (`Username` means username). Any other value (`mobile`) is refused at write time and by `benmore check`; an app that carries one signs in by email. The write gate checks auth: keys however the block is laid out (indent, flow mapping, comments). `auth.mfa` and `auth.oauth` have no effect and are refused: require MFA with `require_mfa_for_roles`, configure providers with top-level `oauth:` (api(at:"oauth")).
