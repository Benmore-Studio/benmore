A completed password reset on a never-verified account also clears its TOTP secret, backup codes and pending enrollment (and, as always, its sessions and API tokens), and consuming a signup verify link revokes every other session and API token and every MCP connector grant of that account (the clicking session stays); the registrant's password still works until the owner resets, so apps wanting full protection should set auth.require_verified or auth.otp. A verify link opened outside the account's own signed-in session asks for the account's password before verifying: a mailbox owner who never chose that password is pointed at password reset, which removes the squatter's sessions, passkeys and MFA; an account with no password is claimed instead. Verifying on a second device therefore needs the password once. Managed social login keeps up to 3 pending nonces per browser (cookie `benmore_oauth_nonce`), so a second sign-in tab does not break the first.
