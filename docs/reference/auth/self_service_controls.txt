Apps may close account self-registration, end-user password recovery, and user-minted API credentials independently: `auth.signup: false` refuses password and OAuth creation of new accounts while existing-account sign-in remains available; `auth.password_reset: false` refuses forgot-password mail and reset-link redemption (operator/CLI password provisioning and required password changes remain available); `auth.api_tokens: false` refuses POST /api/_auth/token and POST /api/_auth/api-tokens while existing-token list/revoke remains, and turns off the API credentials already issued: a `bmr_` API token, and a session from POST /api/_auth/token whether sent as Bearer or cookie, is treated as signed out (protected routes answer 401) while the switch is off and works again if it is switched back on (nothing is deleted). Exchange sessions minted by an older runtime are not marked and last until they expire or are revoked; OAuth access tokens (`bma_`) and the person's own sign-in sessions are not affected. Each defaults on for compatibility. Boolean values accept true/false, yes/no, on/off, 1/0. These are runtime guards; hiding a page is not authorization.
