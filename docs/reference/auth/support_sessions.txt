A support session (POST /api/_auth/impersonate, `api(at:"audit")` `impersonation`) acts on the admin's sign-in and ends with it. (1) It resolves only while the session it was started from is live, whether that session's token was the cookie or a Bearer header: revoke that sign-in (DELETE /api/_auth/sessions/{id}, MCP revoke_session), log it out or let it expire, and the support session answers 401 at once instead of running out its hour. (2) Everything that revokes the admin's credentials - a password change or reset, the required change of a temporary password, the claim of an unverified account, an email change, an operator reset - also deletes the support sessions that admin started; a signed-in password change keeps only those started from the session that made the change. A support session started with a `bmr_` API token names no starting session: it ends with (2), the admin's standing and its own hour, not when that one token is revoked. (3) POST /api/_auth/end-impersonation needs a live support cookie like any request (an expired or idle one answers 400 and restores nothing) and hands the admin's session back (it answers `restored`) with its activity time set to now, so with auth.idle_timeout the admin is not signed out by the first request after it. It restores only a support session started from the browser cookie; one started over Bearer answers 400 (the caller still holds its own token). (4) Both endpoints set the cookie sign-in sets for the app's mode (`__Host-benmore_session` in production) and expire the other name.
