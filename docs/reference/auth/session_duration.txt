`auth.session_duration` is how long a sign-in lasts (default 30 days). Accepted forms: a positive Go duration ("12h", "90m", "1h30m") or whole days ("7d", "30d"). Anything else - a number without a unit (`12`), a week, month or year ("1w"), part of a day ("1.5d"), words ("8 hours"), `0` or a negative value - is refused when app.yaml is written (write_file, edit_file, `benmore push`, `benmore deploy`) and is an error in `benmore check`, with the accepted forms. `0` does not turn expiry off: remove the key for the default, and use `auth.idle_timeout` to end inactive sessions sooner. An app that already carries such a value keeps loading with the lifetime it has had (30 days; the loose spelling "7days" keeps its 7), and every start and reload logs `WARNING: app.yaml: auth.session_duration = "1w" is not an accepted session lifetime; the runtime gives sessions 30 days for it`. The security scan reports such a value as a warning, not as `Session duration configured`.
