admin.yaml, in the app's root, adjusts the /_admin panel table by table: `tables: {<table>: {hidden, readonly, columns, search, label}}`. It is optional; a table with no entry is shown with every column, searched on every column shown and edited as admin_panel_tables describes. Every setting changes the panel only: /api/<table>, the app's flows and the table's access: rule are unaffected. Table and column names are matched without regard to letter case. `hidden: true` takes the table out of the panel (admin_panel_tables). `readonly: true` keeps the table's pages and removes its writes: the list and record pages have no Create, Edit or Delete control (a row opens with View), and POST /_admin/api/<table>/create, /update/<id> and /delete/<id> answer 403 {error:"admin_table_read_only", table, message, docs} and change nothing. On _benmore_users it also closes POST /_admin/set-role (same 403) and the user page has no role form. `readonly: [status, total]` (a list) makes those columns read-only and leaves the rest of the table editable: the record page shows them as values with no input, the create form has no input for them, and a create or update through the panel that names one answers 403 {error:"admin_column_read_only", table, column, message, docs} and saves nothing (send the request without the column). `columns: [name, email, status]` chooses the columns the list page, the record page, the create form and the table's Related list on other record pages show, in that order; a column it leaves out keeps its value when a record is saved, and a create leaves it to its default, so list every column a new row needs. It chooses what the forms offer, not what a request may write: use `readonly` to stop a write. A column no response carries (hidden_columns) is never shown, listed or not. `search: [name, email]` chooses the columns the list page's search box matches; without it the search matches the columns the page shows. A name that is no column of the table is skipped, in both lists. `label: "Customers"` is the table's name in the sidebar. Example: `tables: {orders: {label: "Orders", columns: [number, customer, status, total], search: [number, customer], readonly: [total]}, ledger: {readonly: true}, vault: {hidden: true}}`. Saving the file through the CLI or MCP, and `benmore check`, refuse a key the panel does not read (`read_only`, `hide`, `fields`, a misspelled top-level `tables`), a value of the wrong shape (`readonly` takes true or a list of column names; `columns` and `search` take a list of names; `hidden` takes true or false) and two entries that name one table: such a key would do nothing while the file reads as if it did.
