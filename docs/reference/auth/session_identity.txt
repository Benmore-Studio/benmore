A session answers as its account's CURRENT row: role, verification, deactivation and the email are read from _benmore_users on every request, never from the copy the session row took at sign-in. So when an operator changes an account's email (SQL, an admin flow, a support tool), its open sessions immediately stop resolving anything addressed to the old address (an email-keyed tenant membership, member-of rules, record shares, invites) and pick up what is addressed to the new one; flows see the new `user_email`. The session row's `email` column is informational. A self-service email change is unaffected (it already ends every session), and so is an address changed in the /_admin panel, which ends the account's sessions and tokens too (admin_panel_accounts). The platform dashboard resolves its session cookie the same way, so a dashboard session follows its account when support changes the address.
