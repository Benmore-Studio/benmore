POST /api/_auth/token exchanges a password for a Bearer session token, for clients that keep no cookie. Body (JSON): `{"email": "...", "password": "..."}`. `email` carries the app's sign-in identifier (the username or phone when auth.identifier says so). Optional fields: `mfa_code`, required for an account with an active second factor (a TOTP or backup code; api({at:'mfa'}) endpoints), and `scopes`, a space-separated list such as `contacts:read deals:write` that narrows the session to those scopes. The answer is 200 `{"token": "...", "user_id": <id>, "email": "<the identifier sent>"}`, plus `scopes` when the request named them, with `Cache-Control: no-store`. Send the token as `Authorization: Bearer <token>` on later requests; such a request needs no CSRF token (api({at:'csrf'}) bearer_exemption), and the session lasts as long as a browser session does (session_duration). Refusals: 400 `invalid request` for a body that is not JSON and 400 `email and password required`; 401 `invalid credentials` for a wrong password, an unknown account and a deactivated one alike; 429 after too many failed attempts for the account or from the network; 403 `mfa_required` or `invalid MFA code`; 403 `otp_required` when auth.otp is on and 403 `password_change_required` for an account that must replace its password (both finish at the sign-in page named in `redirect`); 403 `email_verification_required` for an unverified account under auth.require_verified; 403 when the app is social sign-in only (auth.oauth_only) or the address is outside auth.domain / auth.allow_emails; 404 when auth.api_tokens is false (self_service_controls). An account whose role must enrol a second factor (auth.require_mfa_for_roles) gets 200 `{mfa_setup_required: true, setup_token, ...}` and no token (api({at:'mfa'}) required_flow).
