POST /api/_auth/api-tokens mints a persistent API token for the signed-in account: a `bmr_...` secret an integration sends as `Authorization: Bearer <token>` (requests with it need no CSRF token). Body (JSON): `{"name": "<label>", "scopes": "<scopes>", "expires_in": "<optional>"}`. `name` is required (400 `name required`). `scopes` is required (400 `scopes required (use '*' for full access)`) and is ONE string: `*` for everything the account may do, or `<table>:<action>` entries separated by spaces, e.g. `"visit_notes:read labs:write"`. Actions are `read`, `write` (create and update), `delete`, a name a flow's `permissions:` asks for, or `*`; `*:read` covers every table. A comma-separated list is refused (400 `invalid scope action "read,labs:write" ...`), a JSON array too (400 `invalid request`), and scopes beyond the caller's own answer 403 `requested scopes exceed your permissions`. `expires_in` is `<n>d` (1 to 365 days) or `<n>y` (1 to 5 years), e.g. `30d` or `1y`; any other value is 400 `invalid expires_in (use 30d, 90d, 1y)`. Without it the token does not expire, except that a token minted from a POST /api/_auth/token session or from a scoped session expires no later than that session, whatever `expires_in` says (credential_limits): read `expires_at` in the answer. Answer: 200 `{"token": "bmr_...", "name": ..., "scopes": ..., "expires_at": <RFC 3339 time or null>}`. The secret is shown this once; only its hash is stored. Mint from a sign-in: a cookie session (send `X-CSRF-Token`) or the Bearer session of POST /api/_auth/token. An API token, an act-as session and a support session get 403 `create API tokens from a login session outside act-as mode`, a signed-out caller 401, an account already holding 100 live tokens 409 `api_token_limit`, and `auth.api_tokens: false` answers 404 (self_service_controls). GET /api/_auth/api-tokens lists the account's tokens, newest first, as `{"tokens": [{id, name, scopes, last_used_at, expires_at, created_at}]}`, never the secret. DELETE /api/_auth/api-tokens/{id} revokes one: 200 `{"status": "revoked"}`, or 404 `token not found` for an id that is not the caller's own. Listing and revoking need an unscoped credential. Scopes narrow the generated API; a flow that declares no `permissions:`, a server-rendered page's queries and GET /pdf/<page> run as the token's account (credential_limits). Minting and revoking write no audit row (api(at:"audit.account_events")).
