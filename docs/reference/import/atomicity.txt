One transaction per file, committed only after every row has loaded and the streamed sha256 matches. A failure - a bad row, a checksum mismatch, an app shutdown mid-load - leaves ZERO rows from that file in the table. Cost: SQLite has one writer, so every OTHER write to the app fails once its 10 s busy timeout elapses for as long as the load holds its transaction open. Reads are unaffected (WAL), except in a compliance: hipaa app, where every audited read writes its read-audit event first and so waits for the import's write lock (api(at:"compliance") -> read_audit). Treat a large import as a maintenance window, not a background task.
