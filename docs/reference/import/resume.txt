Re-running the identical `benmore import` command resumes automatically - the server returns the existing session when table/format/gzip/sha256/bytes/caller all match one still in "staging". There is no --resume flag. A session left in "staging" for more than 24h with no commit is swept to "failed" on the app's next process start (also when a "running" session is caught mid-load by the same restart, e.g. every platform deploy). In cluster mode (BENMORE_CLUSTER=true) the restart sweep fails only a "running" row whose lease has lapsed, and any process fails one at the next status/commit/cancel call on it (see running_lease), so no manual SQL is needed.
