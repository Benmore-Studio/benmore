Mode A never writes the primary key (it is excluded, as on an auto-CRUD create) - every imported row gets a FRESH id. Correct for a flat catalogue table, but for a relational migration it means parent ids are regenerated and any CSV of a CHILD table carrying the OLD parent id as a foreign key will not match post-import. Mode B (owner-only SQL restore) is the answer when foreign keys must be preserved across tables: it executes the dump's own INSERT statements verbatim, ids included.
