An empty CSV field becomes NULL for a non-TEXT-affinity column and "" for a TEXT column. Set null_as on the create request to override that sentinel for one specific value - e.g. null_as: "\N" for a pg_dump COPY export, null_as: "NULL" for a mysqldump one. NDJSON is already typed by JSON, so none of this applies to it. A column the file's header (CSV) or first object's keys (NDJSON) doesn't name is simply absent from the INSERT - it takes the column's own DEFAULT, never an explicit NULL. The same holds per row for NDJSON: a key a later object leaves out takes the DEFAULT for that row, while a key written as null is NULL. The first object fixes the column set: a later object carrying a key the first object does not have fails the load (row N: NDJSON object has key "x" absent from the first object; cannot add columns mid-stream), so give the first object every key (null where it has no value). Columns the published schema.prisma declares are type-checked like CRUD writes (scalar_writes): an Int needs an integer, a Float a finite number, a Boolean true/false or 1/0 (stored as 1/0), a DateTime a valid date, a String a string; the first bad value fails the whole load with its row number and column. Tables of an app without schema.prisma keep SQLite's column affinity.
