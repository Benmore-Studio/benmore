Optional on create: declare the CSV header / NDJSON key list up front so the server rejects an unknown or protected column (e.g. a source-table export's own `id` primary key) BEFORE any chunk uploads, instead of discovering it at load time. `benmore import` supplies this for CSV automatically (reads just the header line locally, never the whole file). If omitted, load-time validation is NOT symmetric between formats: CSV hard-errors on a header naming an unknown/protected column - the load still aborts atomically (zero rows land), just after the upload instead of before it. NDJSON does NOT hard-error on that case - an unknown/protected key (id, user_id, ...) present in every object is silently DROPPED for the whole file, because the effective column set is only the intersection of the first object's keys with the table's importable columns; the load fails solely if that intersection is empty. A caller that needs the strict CSV-style rejection for NDJSON must supply `columns` explicitly - that is the only NDJSON path that actually catches an unimportable key rather than quietly ignoring it.
