`benmore new` from the hosted CLI creates an app without an mcp.yaml, so the suggested first `benmore deploy` works. After the first deployment, pull the complete remote source into a fresh directory before authoring and explicitly reviewing an optional connector (`benmore docs connector`). Server-created HTML apps and self-hosted framework starters include a digest-bound, read-only list_notes starter manifest projecting id/title/body; it keeps owner exposure, approved writes, export and publication off. Bare deployments of existing apps do not gain demo tools: an existing app opts in by declaring its reviewed tools in mcp.yaml. Reviewed-manifest deploy checks and owner exposure controls apply to every app.
