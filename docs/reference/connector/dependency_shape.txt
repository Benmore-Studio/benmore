A command dependency query must return exactly one column named id (any case; t.id and id AS ID qualify). benmore mcp review, mcp check/inspect, the push write gate and benmore check prepare each dependency query against an empty in-memory database built from schema.prisma or schema.sql (the statement is never stepped and holds no app data) and refuse `dependency "<name>" must return exactly one id column` with the columns it returns. A query the schema files alone cannot prepare (a table or column a migration adds) is left to the runtime, which refuses the prepare with the final error code invalid_declaration naming the dependency.
