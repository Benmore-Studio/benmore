`benmore mcp review <appdir> --reviewed` edits only its own top-level keys (contract_digest, execution_digest, execution_sources: runtime) in the authored mcp.yaml and keeps every other byte: integers (maximum: 100000000 and 9007199254740991 stay as written), quoting, comments and indentation, so a tool added later in the documented two-space style parses. Missing keys are inserted after `version:`; a flow-style (`{...}`) document keeps its flow style, with the three keys appended at the end of the top-level mapping. Review refuses unless the written text decodes to exactly the authored declarations, and the digests hash the decoded manifest, so formatting never changes them: a manifest formatted differently (four-space indentation, floats such as 1e+08) still verifies, and re-reviewing it unchanged keeps its bytes and digests. Omitted optional tools, resources and connections stay omitted; explicit null is invalid. The Notes starter mcp.yaml of benmore new is written the same way (two-space). Review does not open app data, change owner switches or grant connector access.
