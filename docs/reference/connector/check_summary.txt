`benmore mcp check <appdir>` and `benmore mcp review <appdir> --reviewed` print the inspection document as JSON on stdout (the same document as `benmore mcp inspect <appdir> --json`): `source_valid`, `connector_enabled`, `contract_digest`, `execution_digest`, `reviewed_tools`, `inventory` (every route, flow, page, hook, scheduled job and static source file of the app with its connector state), `unmeasured` and `warnings`. It lists the whole app, so it passes 100 KB for a small one; scripts that read it (a deploy gate that compares the digests, a release check) rely on that default, which is why it stays. For a person, add `--summary` to either command, before or after the directory: it prints a few lines of text instead: the verdict and the number of reviewed tools (`mcp check: source valid, 3 reviewed tools`), `contract_digest` and `execution_digest`, the reviewed tools by name with their effect and, where one is declared, approval (the first 40), the inventory as counts by kind and by state (for example `inventory: 212 entries (150 ui_source, 40 crud, ...); 180 unresolved, 20 command-only, ...`), every warning in full, and under `not checked here` what a source check cannot see. After a review it also says that mcp.yaml now carries the digests and that review does not enable access. An app without mcp.yaml reads `no mcp.yaml: the app declares no connector`. `--summary` changes only what is printed: the checks, the exit code (0 when the declared source scope passed, 1 with the refusal on stderr, 2 for a usage error) and what review writes are the same, and a refusal prints no summary. Any other argument after the directory is a usage error.
