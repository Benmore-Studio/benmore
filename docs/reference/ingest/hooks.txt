Each row runs create validation, access/scope checks, protected/computed-column rules, parent visibility and before_insert hooks inside a row savepoint. A refused row is skipped and counted; accepted rows can still commit. A row that names a column the table does not have is skipped and counted too (single create and /batch ignore the unknown key and create the row), so strip extra keys before sending. Streaming ingest intentionally does not run per-row on_insert after-hooks, on_insert flows or webhook subscriptions. Each committed row gets its own audit entry in the ingest transaction, as batch create writes: action insert, the row's id and its stored values. Skipped and refused rows leave none. It emits one table insert notification after commit. Use ordinary CRUD or /batch when the app needs per-row after-effects; use api(at:"import") for an all-or-nothing bulk load without per-row hooks.
