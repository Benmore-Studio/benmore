A refusal says where its rule is documented. A JSON answer carries `docs`, the address of a key of this reference (`"docs": "flows.step_keys"`): read it with api(at:"<docs>") or `benmore api <app> <docs>`. It is on a check finding (`check.findings[]` of write_file and edit_file, check_app, `benmore check --json`); on the auto-CRUD refusals 401 `authentication required`, 403 `forbidden`, `Invalid CSRF token`, `scope denied: ...`, `field_owned_by_command` and `uploads_disabled`, 404 `not_found`, 409 `conflict` and `record is locked by another user`, 413, the 422 of a validators.yaml rule, of a foreign key and of a create with no tenant, 400 `No fields to update` and 507 `storage_limit`; on a flow's 422 input refusal, its `rate_limit` 429, `template_unresolved`, `flow_no_response` and `flow_timeout`; on the app-wide, ingest and lock 429; on the sign-in state codes (`password_change_required`, `otp_required`, `mfa_required`, `email_verification_required`, `email_unverified`, `api_token_limit`); on promote's `upgrade_required`; and, as `_meta.docs` beside `_meta.error_code`, on a failed connector tool call. A text refusal (a refused write_file, edit_file or `benmore push`, `benmore check`, the error list of a push) ends each issue with one more line, `docs: api(at:"flows.step_keys")`. The field is absent where no key states the rule, so read it as optional; every other field of an answer is as it is without it.
