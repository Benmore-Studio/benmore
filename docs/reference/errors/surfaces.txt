get_errors(app, source?, level?, since?, unresolved?, limit?, group_key?) reads scrubbed groups, samples, counts, request IDs and delivery counters (viewer access, limit capped at 200). since accepts RFC3339 or a positive duration such as 1h. resolve_error(app, group_key) requires editor access and audits resolution; a new occurrence reopens the group. test_error_reporting(app) requires editor access and sends fixed synthetic Sentry/Slack events, bypassing group throttles but preserving delivery limits; returns each sink's status/ok/rejected/muted/configured and reporter counters. get_client_errors remains available; prefer get_errors. CLI: benmore errors <app> [--since 1h] [--source server|client] [--level error|warning|fatal] [--limit 200] [--follow], and benmore errors test <app>; both accept --env dev|prod. Follow prints changed snapshots every two seconds until interrupted. The app Errors dashboard provides filters, stack/context/breadcrumb detail, request-log links, editor resolution and delivery tests. Sentry status distinguishes configured, connected (successful delivery), not configured, rejected and currently rate-limited.
