These /api/ refusals answer the JSON envelope, with their text in `error`. (1) Rate limits: the app-wide request limiter (RATE_LIMIT_PER_MIN), the hosted platform's front-door limit and the NDJSON ingest limit answer 429 `{"error":"Rate limit exceeded. Try again later."}` with a Retry-After header. Outside /api/ (a page, a form post) the app-wide and front-door refusals are text. (2) `admin required` (403) on /api/_analytics/summary, /funnels and /funnel, and the funnel's 400. (3) These routes send their JSON bodies as application/json: /api/_audit (401, 403), /api/_docs, /api/_openapi and /api/_schema (401), /api/_devices (400, 401), /api/_schema/<table>/fields, POST /api/_auth/token, and the 429 of POST /api/<table>/<id>/lock. (4) GET /api/<table>/<id> with an id that is not the row's canonical spelling (01, 1.0) answers the missing row's 404 `{"error":"Not found"}`. Not the envelope: transport refusals of the /api/_mcp connector routes (text), the 404 of a built-in route whose feature is switched off (/api/_upload, /api/_files, /api/_my-data, /api/_auth/users, the passkey and account-settings routes: text `404 page not found`), a form post to /api/_switch_group (text; a JSON client gets JSON) and the HTML fragment an htmx form receives for a validation error. So parse a body as JSON only when its Content-Type is application/json, as `bm` does.
