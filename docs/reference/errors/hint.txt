Client code should branch on the status, then on `error` where it is a short code (conflict, not_found, forbidden, flow_no_response, template_unresolved), and show the user `message` when there is one, else `error` (a validation or CSRF refusal carries only its sentence, in `error`). On a 5xx, show `request_id` (or the X-Request-Id header) and find the cause with get_request_logs.
