A SQLite constraint rejection of the row UPDATE (for example UNIQUE, NOT NULL or CHECK) answers 400 on single-record PATCH, batch PATCH and /api/_transaction. The answer is a safe constraint explanation without table, column or submitted-value details. A rejected update leaves its row and audit unchanged, and a later batch/transaction rejection rolls back earlier pending writes and audits. Actual internal database faults still answer 5xx with a request id; authorization and row-scope gates run before the mutation as usual.
