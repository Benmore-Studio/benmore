`features.docs: false` in app.yaml keeps only the canonical GET /api/_openapi available to an admin on an unscoped credential; ordinary app users and scoped admin credentials cannot use it. /docs, /api/_docs, /openapi.json, /api/openapi.json and /api/_schema are not registered (404; on an HTML-stack app /docs falls through to the app's index page). Without /api/_schema the schema-driven components (api(at:"components")) cannot render, so keep docs on, or use `features.docs: auth`, in an app that uses them. The full developer/admin document includes custom on.request flows and their declared contract schemas; ordinary enabled docs omit custom flows. The declarations are descriptive, not runtime validation. info.version carries a fingerprint of the served flow contracts for every audience: an ordinary caller can see that admin-only contracts exist or changed (a version suffix appears or moves), never their content. See api(at:'flows') request_contract.
