Create<Model> lists the columns a generic POST /api/<table> stores and Update<Model> the columns a PATCH stores (plus `_expected_updated_at`); both schemas set `additionalProperties: false` (the runtime itself drops an unknown property without an error). They leave out computed.yaml columns, a workflow's state column, command-owned columns and the membership role_field, which every write drops or refuses, and a computed NOT NULL column is not `required`. Custom fields (POST /api/_schema/<table>/fields) are listed. The tenant key is in Create only, optional, because a platform admin's create keeps it (everyone else's row takes the session's tenant); with groups.role_field the membership identity column is in Create only. The same rule decides `writable` in /api/_schema: api(at:"components") → the_descriptor.
