Every table is served at /api/<table> (auto-CRUD, record locks, sharing) by the same router as the framework's own endpoints under /api/_... A table whose routes cannot register next to a framework route - `_upload`, `_schema`, `_query`, `_jobs`, `_notifications`, `_auth`, `_transaction`, `_broadcast` and the other /api/_<name> paths the app registers - is refused when schema.prisma is written (schema.sql for an app without schema.prisma; write_file, edit_file, `benmore push`, `benmore deploy`) and is an error in `benmore check`. The refusal names the model, the table, the route and a name that works: `schema.prisma: model Thing maps to table "_upload", whose route POST /api/_upload is a route the framework registers itself ... put @@map("upload") in the model`. The refused names are not a fixed list: the check registers the app's framework routes from source and tries the table's routes against them, so it follows the features the app has on (`_csrf` collides only in an app with auth) and never refuses a name that loads (`_foo` is served at /api/_foo; `_benmore_*` and `sqlite_*` tables get no routes). A table that only a migrations/*.sql file creates is not checked. Do not start a table name with `_`: /api/_... is the framework's, and a feature switched on later or a new release can claim a name that is free today.
