An app loads one schema file: schema.prisma when it declares at least one model, otherwise schema.sql (schema.yaml is shorthand for schema.sql). The other file is not read: the tables only it declares are not part of the app's schema and edits to it are not applied, though tables already in the database keep their rows. A schema.prisma write (write_file, edit_file, `benmore push`, `benmore deploy`) into an app whose schema is schema.sql is refused while it leaves out a table schema.sql declares, because it would take schema.sql's place: `schema.prisma not written: this app's schema is schema.sql ...`, listing those tables. To add a table to such an app, declare it in schema.sql (in schema.yaml when the app has one). To move the app to schema.prisma, write a schema.prisma that declares every table of schema.sql as a model (`@@map("<table>")` keeps a table's name); the tables and their rows stay as they are, and schema.sql is not read from then on. A schema.yaml is refused beside a schema.sql that is written by hand (write_file, edit_file, `benmore push`, `benmore deploy`; an error in `benmore check` when both files are already there): an app with a schema.yaml writes its schema.sql from it when it loads, unless schema.sql is the newer file, replacing the file it has. Keep such an app's tables in schema.sql and no schema.yaml beside it. A schema.sql the app wrote from schema.yaml starts with `-- Auto-generated from schema.yaml`; an app with that file edits its schema.yaml freely. `feature_install` does not put a pack's Prisma models into an app whose schema is schema.sql or schema.yaml: api(at:"feature-packs") safety.
