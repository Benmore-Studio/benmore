Supported stored scalar types are Int, BigInt, String, Boolean, Float, Decimal, DateTime and Bytes; ? makes a scalar nullable. Object and [] relation fields must name a model declared in the same schema (forward declarations work); framework-managed User, Session and AuditLog references retain their existing compatibility behavior. The write gate and benmore check refuse unsupported Json/enum types, misspelled or undefined model references and scalar lists such as String[], with the model, field and line. Use related child models, or explicitly serialize JSON into a String field. This is an authoring/check guard: existing deployed schemas still load, no omitted values are recovered, and it does not add JSON or scalar-list persistence. `benmore check` warns about a money-named column stored as Float: binary floats cannot hold decimal currency exactly, so store integer cents (`amountCents Int`).
