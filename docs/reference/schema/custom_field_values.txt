A custom field is a real, nullable column added to that instance's database, not to schema.prisma. Example: `POST /api/_schema/orders/fields` with `{"name": "priority", "type": "INTEGER", "description": "1 = urgent"}` answers 201 `{"column":"priority","status":"created","type":"INTEGER"}`. From then on it is a column like any other of the table: every caller who may write the table sends it in POST and PATCH bodies, reads it in rows and filters and sorts by it (`?priority=3&sort=priority&order=desc`), under the table's own access rules, and GET /api/_schema lists it as writable. Rows that existed before hold NULL. Send values of the declared type. DELETE drops the column with every value in it; a column that schema.prisma declares is not a custom field (404). Each add and remove writes an audit entry (`add_field`, `remove_field`). The field lives in the database it was added to, not in the app's source: another instance of the app has it only once it is added there, and a new database (`benmore test`, a new instance) starts without it, so a column the code depends on belongs in schema.prisma. A signed-out or non-admin caller gets 403 `{"error":"admin required"}` on all three routes.
