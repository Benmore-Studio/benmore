A field, an @map column, an @@map table, a schema.yaml or schema.sql name and a custom field may be an SQL reserved word: order, group, from, to, index, values, default, check, table, limit, transaction, set, select, where and the rest of SQLite's reserved words. The DDL Benmore generates writes such a name quoted (CREATE TABLE, added columns, indexes, foreign keys, the @updatedAt trigger, full-text sync triggers, computed.yaml and encrypted-field triggers, schema.yaml tables). Only reserved-word names are affected, so an existing app gets the same migration files and no schema change. Auto-CRUD quotes the column in list filters (?col=, where[col]=, col__gte=), ?sort= / orderBy, ?fields= and the short-query search fallback. Two things to know. (1) SQL you write yourself (flows, hooks, computed.yaml expr:/sql:, aggregates, migrations/ files, `benmore sql`) must quote the name: SELECT "order" FROM steps. (2) A column named like a list parameter (order, sort, limit, offset, page, per_page, fields, include, cursor, q, orderBy, order_by, as_of) is filtered as where[order]=2 or with an operator suffix (order__gte=2), because ?order=asc is the sort direction. A name that is not a plain identifier (letters, digits and _, not starting with a digit) is refused. To store a field under a column name that needs no quoting, map it: `order Int @map("sort_order")` (the API then uses sort_order).
