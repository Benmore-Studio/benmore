validators.yaml holds per-table rules checked on every auto-CRUD create/update (batch, ingest, /api/_transaction and group bootstrap too): `deals:
  - rule: "end_date > start_date"
    error: "End date must be after start date"`. A rule is ONE comparison `<column> <op> <column, number or 'quoted string'>` with a space on each side of one of != >= <= = > <, or a bare column name (truthy). The write gate and `benmore check` refuse what the evaluator would skip or always pass: keys other than rule/error, an empty rule, a table not in the schema, a rule with no column on either side (a misspelled column), `==`, AND/OR/&&, functions and unquoted dates. `>`/`>=`/`<`/`<=` compare the WHOLE operands: as numbers when each side is a number, as instants when each is an ISO-8601 date or date-time (`2024-03-05`, `2024-03-05T10:00`, `2024-03-05 10:00:00`, RFC3339; a zone-less value is UTC), otherwise as text. `=`/`!=` compare text. A NULL column operand (sent as null, or an omitted nullable column with no default) makes the rule pass, as a SQL CHECK does: `end_date >= start_date` accepts a row with only one of the two dates; add a separate rule or a NOT NULL column to require one. A bare word that is not a column of the table stays a literal. On an update the rule sees the stored row merged with the change, so a stored row that breaks a rule can't be updated until the change fixes it. On create, an omitted column used by a cross-field rule receives its physical SQLite default before the rule runs (single, batch, transaction, ingest and group bootstrap). The evaluated default is bound into that same insert, so expression defaults cannot change between validation and persistence. Explicit values, including null, are never replaced, and defaulted columns are not added to the hook _submitted list. Autogenerated primary keys and computed-trigger results are not available before insert.
