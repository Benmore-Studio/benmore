Configuration the app's load refuses is refused at write time (write_file, edit_file, `benmore push`, `benmore deploy`) and is an error in `benmore check`, filed on the file that holds it: encrypted.yaml or app.yaml encrypted: naming a table or column the app does not have (blind_index fields included); app.yaml versioned: naming a missing table; computed.yaml naming a missing table, column, trigger table or trigger fk, or whose expr/sql reads a missing column (checked by installing its triggers into an in-memory copy of the schema); for computed.yaml a table or column only a migration creates counts as missing, because the load installs computed triggers before it runs migrations/ (a database that has not run the migration yet - a new instance, a promote, `benmore test` - cannot load), so declare it in schema.prisma; @@fulltext naming a field the model does not have. A table counts when schema.prisma declares it or one of the app's own migrations/*.sql creates or renames it into place (a framework table is refused in all three files: framework_tables); a column when the model declares it or such a migration adds or renames it (migrations the Prisma step generated are not read). Columns of a table a migration creates are not checked. A schema.prisma write that removes a model or field another file still names is refused the same way, naming the file; a removed field's column stays in the live database, but a new database (a new instance, `benmore test`, a first promote) is created without it. Remove the reference first, or write both in one batch: `benmore deploy` writes schema.prisma, then migrations/, then app.yaml and the rest, each with reload:false and pending_paths naming the later .prisma/.sql/.yaml files; a reference the schema write leaves in one of those is judged when that file is written (the answer lists such files in cross_file_pending), the batch reloads once at its end, and if one of them is refused nothing reloads (schema.prisma stays saved but unapplied until the batch is fixed and deployed again). A multi-file `benmore push` defers a schema file's reload the same way. References the app loads with (an access: rule, a hook or a workflow on a missing table, a ws_rooms rule on a missing table or column) remain warnings; validators.yaml has its own refusal (cross_field_validators). retention.yaml, computed.yaml and app.yaml `aggregates:` are checked the way the app reads them (derived_config).
