Send updated_at exactly as read, retaining fractional seconds. Reads preserve RFC3339 nanoseconds; fresh SQLite-space and API timestamps compare by the same instant. On tables with updated_at, canonical PATCH, batch, transaction and restore updates advance the stored version, including rapid writes or a clock behind the prior value. PATCH and transaction updates carrying _expected_updated_at compare the exact stored timestamp in the active mutation transaction: stale or rounded tokens are refused, and two writers using the same base cannot both succeed. Batch updates have no per-row concurrency token: an `_expected_updated_at` inside `fields` is ignored (the update is applied), not checked and not refused. Authored SQL must maintain its own versioning contract.
