GET /api/_schema (auth-gated) is the per-user source. Per field: control (text|textarea|number|email|tel|url|image|file|date|datetime|time|checkbox|hidden), type (the declared SQL type), required, default, relation {table,column}, masked + writable FOR THIS CALLER. `writable` is true when a create by this caller stores the value it sends for the column (and the caller does not read the field masked). It is false for computed.yaml columns (expr and aggregate), a workflow's state column (only a transition moves it), a column a command owns (`command.owns`), the tenant key (true only for a platform admin, whose create keeps an explicit tenant), the membership table's role_field, and the owner, timestamp and credential columns. Custom fields are listed and writable. Two columns are writable on create only, and a PATCH names them in X-Stripped-Fields: the tenant key for a platform admin and, with groups.role_field, the membership identity column. The declared type picks the control before the column name does: BOOLEAN is checkbox, DATETIME/TIMESTAMP is datetime (a DATETIME named date, *_date, dob, birthday or birthdate stays date), a SQL DATE is date, TIME is time. `default` is the column default as a value: `@default("")` is the empty string, `@default(100)` is 100, `@default(false)` is false; a default computed at insert (now(), uuid(), any expression) or NULL is left out. Per table: label, capabilities (soft_delete, …), and ops {read,write,update,delete} the caller may perform: its access mode AND its RBAC scope (role scopes or a token's scopes), so a table with no allowed op is left out for a non-admin. Hidden credential columns are never listed. Components read it; you don't.
