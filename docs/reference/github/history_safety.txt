Before initialization, snapshots and auto-commits, Benmore repairs mandatory ignore rules and stages only source paths. Protected paths include data.db and its WAL/SHM, .benmore, uploads, env.yaml, secrets.yaml, .env/.env.*, *.key, *.pem, *.log, the root Benmore directory and a restore's database copies (.restore-<digits>/ and .pitr-<digits>/ at the top of the app directory; see api(at:"recovery") database_restore). Nested ignore negations cannot bypass staging. Already-tracked or staged protected paths block history operations; reverts also check the target commit and runtime directory obstructions. GitHub push audits every reachable commit, including deleted paths and merge parents, and sends the audited commit. Existing contaminated history requires operator remediation; removing a file from the latest tree does not remove it from older commits. No automatic history rewrite or credential cleanup occurs. Secrets embedded in ordinary source files are outside this path-based protection. History tools (log, show, revert, snapshots, GitHub push) also refuse a repository whose local git config holds a key outside what `git init` and Benmore write, or whose metadata points outside the app's own `.git` directory (a `.git` file or symlink, `commondir`, object alternates, symlinked refs, objects or packs); both answer `operator cleanup is required`.
