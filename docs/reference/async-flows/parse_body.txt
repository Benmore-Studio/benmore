A `run: parse` body step works in an async flow. When the flow has one, the job carries the request body as that step reads it (form fields or decoded JSON, after `verify:` and the 1 MiB cap; a larger body answers 413 instead of 202), and the step reads it in the worker. A body that is not valid JSON is queued as its error, so the parse step fails the job when it runs, as it fails the flow inline. Values in it named like hidden columns are redacted when the job is read back, like the rest of the payload. `source: headers` is not carried; read the headers you need in a sync flow.
