A job's error is redacted before it is stored, answered on status_url, listed by GET /api/_jobs and MCP describe_jobs, or written to the journal (JOB RETRY / JOB FAILED): the app's env values and the values a step derived from one become [redacted] (as written and URL-escaped), URL query values and credential-shaped text too, and the text is one line of at most 2 KiB - what the synchronous path's step_error and FLOW ERROR line show. Rows stored unredacted are redacted when they are read. Cron runs, data-event flows, scheduled flows and the /_admin/tools runner report their failures the same way. A secret the app did not get from env (one read from a table) is redacted only when it has a known key shape.
