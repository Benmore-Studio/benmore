Add `mode: async` to `on.request` to flip a flow from inline-execution to enqueue-and-return. The request is answered 202 Accepted immediately with `{job_id, status_url, status: "pending", flow}`. The background worker picks the job up and runs the flow's steps with the input captured from the request. Clients poll status_url. The job runs once: a failed run marks it failed with that run's error, unless the flow opts into retries with `on.request.max_attempts` (see `retries`). A flow job interrupted by a worker crash is marked failed, unless the flow file declares `idempotent: true` at the top level (next to `on:` and `jobs:`): then it is requeued and runs again, at least once. Declare it only when every side effect is safe to replay.
