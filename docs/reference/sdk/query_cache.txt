bm.query.fetch deduplicates current reads by key and honors staleTime. invalidate marks matching keys stale and optionally starts a new read; set replaces a cached value. Both supersede older in-flight reads, so their eventual data/error cannot overwrite current state or clear a newer pending request. Superseded fetch promises still settle for their original callers; the underlying fetcher is not aborted. A failed optimistic mutate restores only keys it still owns; a later set, successful fetch, invalidation or optimistic edit takes ownership, so an older rollback (including a custom rollback callback) cannot replace newer state. Overlapping failed edits unwind past other failed snapshots. A newer failed read keeps its error while the rejected edit rolls back, and a read started after the optimistic edit can still publish its result. Use subscriptions for cache-driven rendering and fetch persisted rows after successful receipt-only mutations.
