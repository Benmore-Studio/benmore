bm.query.read/table register their keys for live invalidation unless live:false. Named change events refetch that table's registered keys. A tableless {action:'refresh'} hint (used for private/member-of changes) refetches all registered live keys, so another authorized member's edit reaches cached lists and summaries. Generic and named hints coalesce over the existing 50ms window; unrelated custom caches and keys never registered for live updates are untouched. Refetches use the current server access rules. Session changes cancel queued invalidations and clear the live-key registry; older pending reads cannot replace the refreshed data.
