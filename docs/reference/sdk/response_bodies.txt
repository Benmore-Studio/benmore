bm.api (raw and convenience forms) and bm.flows read a response by its Content-Type. JSON (application/json or any +json type) is parsed; a 2xx text/* answer (CSV, plain text, HTML) is its text, a string; a 2xx answer of any other type (an image, audio, PDF or ZIP, as a `run: proxy` or `run: serve_file` flow answers) is a Blob; an empty body, a 204 and a HEAD request are null. A non-2xx answer that is not JSON is `{error, body}`: `body` is the text as received and `error`, which becomes the thrown message, is that text when it is one short line of plain text, else `Request failed (HTTP <status>)`; the convenience forms and bm.flows throw it. A bm.flows call to a GET or HEAD flow sends the params no `:path` segment uses as the query string (objects and arrays as JSON text, null and undefined left out), plus the fields of a body passed to it (FlowForm and FlowButton pass one; params win); the generated FlowMap types a GET or HEAD flow as `(params) => Promise<...>`, with its path parameters and declared `inputs:`. See api({at:'flows'}) → proxy.browser.
