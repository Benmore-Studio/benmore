Successful native password/signup/passkey session creation, logout, MFA enrollment-session completion, tenant switching/bootstrap and impersonation/act-as changes clear bm.query data/errors/fetchers before notifying existing subscribers. Old pending reads and mutation settlements cannot republish or invalidate the new session's cache; original promises still settle for their callers. The shared bm.live connection rebinds to the current session, ignores queued events from its old connection and closes at logout. Refused authentication and unfinished OTP/MFA challenges do not claim a new session; signOut rejects a refused logout. SDK requests to the default native /verify-mfa and /verify-otp completion routes also reset the cache. Call await bm.auth.refreshMe() after custom authentication routes, custom tenant switches or session changes made outside bm: it clears scoped queries, then rereads the profile. Render the cleared state and load the new account's views; keep application-owned state, bm.createStore() stores and persistent bm.cache data scoped to the account separately.
