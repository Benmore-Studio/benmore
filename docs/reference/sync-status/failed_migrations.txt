A generated migration that fails is kept in the instance's migrations/ as `<name>.sql.failed` (one per distinct failure) for inspection; the app log (`benmore logs`) has the error. It is the instance's debris, not app source: the manifest lists it apart (`failed_migrations`), sync-status prints it under a note without counting it as drift (exit 0 if nothing else differs), pull never writes it and promote never copies it. The instance deletes it the next time its schema migrates (a fixed schema.prisma, a promote that applies, or schema.prisma put back to the applied schema); `benmore delete-file migrations/<name>.sql.failed --app <app> --env <env>` removes it sooner. The runner's quarantine of a hand-written migration that failed, `<name>.sql.failed.sql`, is different: it stays app source until you fix it and restore its .sql name.
