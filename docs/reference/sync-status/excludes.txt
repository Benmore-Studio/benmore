Manifests and pull tarballs exclude `data.db*`, `env.yaml`, `.git`, `.benmore`, `uploads`, logs, runtime workspace dirs, and generated `src/bm.d.ts`. Env vars are represented by key name only, never values. `pull` and `sync` never write files that run on the developer's machine when another collaborator plants them: any hidden directory outside `static/` except `.well-known` and `.github`, and editor/agent config directories such as `.vscode`, `.claude`, `.cursor` and `.git` anywhere, `.mcp.json`, `.envrc`, `.devcontainer.json`, `*.code-workspace`, `opencode.json`, `crush.json`, `.aider.conf.yml`, `.nvim.lua`/`.exrc` and `mise.toml`; they are listed as skipped and ignored by `sync-status`. The server leaves those same paths out of the pull tarball and out of the manifest's `files` (it lists them separately as `pull_denied`), so a CLI without this deny-list never receives them or reports them as missing. Hosted write tools (write_file, edit_file, apply, feature_install) and the legacy archive deploy refuse the named auto-run config outside `static/` (`.vscode/`, `.claude/`, `.cursor/`, `.idea/`, `.mcp.json`, `.envrc`, `*.code-workspace`, ... and Windows aliases such as `CLAUDE~1`); other hidden directories such as `.sdd/` are accepted. `deploy` and the save hook keep such files local, an explicit `push` of one fails with that reason, `write_file` dry-run (the local edit validator) still passes, and an MCP review digest leaves them out. `sync` pulls an app whose display name is not one plain directory name (or is a Windows short name like `CLAUDE~1`) into a directory named after its subdomain. New app names may not hold a hidden, parent or Windows short-name segment or invisible characters, and `GET /platform/apps` hands an older name that breaks that rule out as the subdomain in `name` (the original in `display_name`), so older CLIs sync it there too.
