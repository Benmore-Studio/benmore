Manifests and pull tarballs exclude `data.db*`, `env.yaml`, `.git`, `.benmore`, `uploads`, logs, runtime workspace dirs, and generated `src/bm.d.ts`. Env vars are represented by key name only, never values. `pull` and `sync` never write files that run on the developer's machine when another collaborator plants them: any hidden directory outside `static/` except `.well-known` and `.github`, and editor/agent config directories such as `.vscode`, `.claude`, `.cursor` and `.git` anywhere, `.mcp.json`, `.envrc`, `.devcontainer.json`, `*.code-workspace`, `opencode.json`, `crush.json`, `.aider.conf.yml`, `.nvim.lua`/`.exrc` and `mise.toml`; pull lists them as skipped. The CLI does not upload them on its own either: `deploy` and the save hook leave a hidden directory outside `static/` and the auto-run config in the workspace, and `deploy` prints how many files it did not upload and what keeps each one local (`.scratch/ (12), .mcp.json`). So a scratch or working directory an agent keeps in the app directory (`.scratch/`, `.sdd/`) is not published to the app or its git history; a file the app needs belongs in a plain directory, which is uploaded like any other source (`scratch/` and `tools/` are source). `.gitignore` does not decide what is uploaded: `deploy` uploads a file the workspace's root `.gitignore` excludes like any other file, and after the upload prints a warning on stderr with the number of such files and the paths of up to 10 of them; the exit code and the uploaded set are the same as without a `.gitignore`. To keep a file out of a deploy, put it in a hidden directory outside `static/` or outside the app directory; `benmore delete-file <path>` removes one that was uploaded. `push <file>` sends the file it is given in the same way and prints the same warning under its own name (`push: warning: 1 uploaded file(s) match this workspace's .gitignore, which push does not read: notes/todo.md`), once per push, for the files that push wrote; the workspace is `--app-dir` or the app directory above the file, and a loose file pushed with `--app` from outside an app directory gets none. The save hook pushes a saved file that `.gitignore` excludes like any other and prints nothing when the save worked, so no warning comes from the hook. The warning reads only the root `.gitignore` and understands blank lines, `#` comments, `*`, `?`, `**` as a whole path segment (`**/x`, `x/**`, `a/**/b`), a leading or inner `/` (the pattern is anchored to the app directory), a trailing `/` (directories only) and `!` negation; the last matching line decides, and nothing below an excluded directory is re-included. A line with a backslash escape or a `[...]` character class is not understood and never causes a warning; neither does a file below a directory that has its own `.gitignore`. Matching is case-sensitive. Files `deploy` leaves out anyway (the excludes above, hidden directories, auto-run config) are never named, so the `.gitignore` a new app starts with produces no warning. `sync-status` reports these workspace files as `kept_local`, apart from `files` and never as drift (`local_only` means a file deploy would upload that the server lacks). It reports the same kind of file held by the instance (an earlier deploy or a hosted write tool put it there) as `server_kept`, also not drift: `benmore delete-file <path>` removes one from the app, and its earlier content stays in the app's git history (see api(at:"github") `history_safety`), so replace any credential such a file held. Everything below `static/` is served app content and is uploaded whatever its name. The server leaves those same paths out of the pull tarball and out of the manifest's `files` (it lists them separately as `pull_denied`), so a CLI without this deny-list never receives them or reports them as missing. Hosted write tools (write_file, edit_file, apply, feature_install) and the legacy archive deploy refuse the named auto-run config outside `static/` (`.vscode/`, `.claude/`, `.cursor/`, `.idea/`, `.mcp.json`, `.envrc`, `*.code-workspace`, ... and Windows aliases such as `CLAUDE~1`); other hidden directories such as `.sdd/` are accepted. An explicit `push` of auto-run config fails with that reason; an explicit `push` of a file in another hidden directory sends it and notes that only the server and this workspace hold it; `write_file` dry-run (the local edit validator) still passes, and an MCP review digest leaves them out. `sync` pulls an app whose display name is not one plain directory name (or is a Windows short name like `CLAUDE~1`) into a directory named after its subdomain. New app names may not hold a hidden, parent or Windows short-name segment or invisible characters, and `GET /platform/apps` hands an older name that breaks that rule out as the subdomain in `name` (the original in `display_name`), so older CLIs sync it there too.
