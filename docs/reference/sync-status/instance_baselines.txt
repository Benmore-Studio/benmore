`.benmore/remote.json` keeps one baseline per instance. Its top level is the workspace's own (the instance last pulled, or first written to); a push, delete-file or deploy to another instance, such as the `benmore push <file> --env prod` hotfix from a dev workspace (or `--app` naming another app), records under `other_instances` by that instance's subdomain and leaves the workspace's own baseline alone, so the next ordinary dev push is judged against dev. Each instance's guard uses its own baseline: a further push to prod is judged against what this workspace last wrote there, and an instance this workspace has never written to has no baseline, so a file that differs there is a conflict. A pull of another instance makes it the workspace's own baseline and keeps the previous one under `other_instances`. A remote.json from an older CLI loads as the workspace's own baseline; an older CLI reads only the top level and drops `other_instances` when it rewrites the file.
