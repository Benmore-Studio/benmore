Active bm.notifications.onNew subscriptions reset their inbox baseline and cursor after native SDK sign-in, tenant/act-as changes and auth.refreshMe(), and pause at logout. Delayed reads from the prior session cannot invoke callbacks, change the new cursor or block its drain. Unsubscribe also removes the session listener. New-session baseline rows are not replayed; normal live delivery and retry limits still apply. Clear application-owned rendered notifications on account changes separately; this does not erase callbacks already delivered before the change.
