In-app notification inbox. Create one with a hooks.yaml `notify:` entry (fires on the writes that run hooks: auto-CRUD, workflow transitions, groups bootstrap, approved MCP commands) or with a flow's `run: notify` step (any flow: request, cron, async job, data event). There is no HTTP endpoint that creates a notification: the API below reads, marks and deletes the caller's own. Each new notification sends the recipient (only) an SSE/WebSocket `change` event for table `_benmore_notifications`. A `/ws` connection that sent a table `subscribe` receives it when the subscribe names `_benmore_notifications`; SSE and a connection that never subscribed always do.
