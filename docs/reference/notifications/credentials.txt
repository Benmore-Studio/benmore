Scoped API tokens and scoped Bearer sessions need `_notifications:read` for list/count and `_notifications:write` for mark-read, read-all and delete. Write also grants read, following the shared scope contract. A missing required scope returns 403; login sessions and unscoped tokens are unaffected. Scoped credentials can mark or delete only their own notifications: a foreign or missing notification returns 404, including for a scoped admin. Deleting another user's notification requires an admin console with an unscoped credential. The same credential read gate applies to the server-rendered notification_count badge and notification-specific SSE/WebSocket hints: without inbox read authority the badge key is absent and no inbox hint is delivered. Role-derived app-table scopes do not remove a normal login's personal inbox.
