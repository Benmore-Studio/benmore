Scoped API tokens and scoped Bearer sessions need `_notifications:read` for list/count and `_notifications:write` for mark-read, read-all and delete. Write also grants read, following the shared scope contract. A missing required scope returns 403; login sessions and unscoped tokens are unaffected. Scoped credentials can mark or delete only their own notifications: a foreign or missing notification returns 404, including for a scoped admin. Deleting another user's notification requires an admin console with an unscoped credential. The same credential read gate applies to notification-specific SSE/WebSocket hints: without inbox read authority no inbox hint is delivered. The server-rendered notification_count badge is a page value, and a page is never rendered for a scoped credential: a page that requires sign-in answers it 403 `scoped_credential_page` whatever its scopes name, and on a page with no gate the badge key is absent for it, as for a signed-out visitor (api(at:"auth.credential_limits")). A scoped credential reads the count from GET /api/_notifications/count. Role-derived app-table scopes do not remove a normal login's personal inbox.
