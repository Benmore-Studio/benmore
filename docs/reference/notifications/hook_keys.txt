`notify:` takes the recipient user id; `notify_title:`, `notify_body:`, `notify_link:` and `notify_type:` (info | success | warning | error) are sibling keys on the same entry. A bare `title:` or `body:` is not a notify key (hooks.yaml rejects `title:`; `body:` belongs to `webhook:`). A hook fires only for writes that run hooks.yaml (api({at:'hooks'}) → triggers): a flow's or cron job's own SQL write never fires it, so notify from the flow with `run: notify` (flow_step above).
