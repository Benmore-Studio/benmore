`run: notify` with `with: { user_id, title, body?, link?, type? }` creates one notification for the user whose id `user_id` renders (a whole number, e.g. `${{ steps.task.outputs.assignee_id }}`; to notify several users put the step in a `for_each:`). It is stored and announced exactly like a hook `notify:` - same table, same type and link rules, same 1,000-per-user retention, counted by /count and `{{notification_count}}`, and the live event reaches only the recipient's streams whoever ran the flow (a cron job included), so bm.notifications.onNew fires for it. A recipient id that names no user fails the step and stores nothing (a flow can catch it with `on_error:`); title must not be empty. In a `transaction: true` flow the row is part of the transaction and is announced after COMMIT. Outputs: `steps.<id>.outputs.id` and `.user_id`. Full example: api({at:'flows'}) → notify_step.
