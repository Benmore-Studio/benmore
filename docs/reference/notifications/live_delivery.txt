bm.notifications.onNew establishes a latest_id baseline, then drains new notifications in ascending ID order across bounded pages. It includes new rows another tab already marked read, coalesces concurrent insert events, and suppresses pending callbacks after unsubscribe. GET /api/_notifications returns latest_id for the caller's complete inbox; after_id=<non-negative integer> selects higher IDs in ascending order (limit max 100). Normal lists retain unread-first ordering. This is a live subscription, not a durable delivery receipt: initialization, disconnected periods, retention cleanup and request failures can limit delivery; a failed drain resumes from the last delivered ID on the next insert event.
