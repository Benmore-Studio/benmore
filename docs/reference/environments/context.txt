`benmore use dev|prod` pins an environment (persisted, kubectl-style); `benmore whoami` shows the pin and `benmore use none` clears it. Every command that acts on one instance of an app takes `--env dev|prod` for one call, written anywhere after the command name, and `benmore help <command>` shows it. The instance is chosen in this order: `--env`, else the pin, else the command's default. Build and data commands (push, pull, deploy, delete-file, sql, logs, tail, probe, api, describe, decode, audit, health, restart, git, check, users, restore, integrity-check, rotate-key, encrypt-backfill, blind-backfill, publish, unpublish, feedback-widget) default to dev when the app has a dev instance, else prod. errors, analytics, requests, security-scan, testing-status, upload-url and revoke-session default to prod once the app has been promoted, else dev. `benmore feedback <app>` with no instance named lists both instances (each item carries `env`) and sends an id action (show, status, comment, delete, resolve, reopen) to the instance that holds the id; an id both instances hold is refused until `--env` names one. reset-seed refuses to run without `--env` or a pin. For `env` (variables) and demo-password the flag is the scope written; with no flag and no pin the value is shared by both instances. Commands that change an instance's code, data or key print `target: <command> → app <app>, environment <env> (<source>)` on stderr before sending anything: push, deploy, delete-file, sql --write, rotate-key, encrypt-backfill, blind-backfill, and feedback status, comment, delete, resolve and reopen. dev and prod each have their own encryption key, so `benmore rotate-key`, `benmore encrypt-backfill` and `benmore blind-backfill` change only the instance named. App-level commands have no instance to choose: delete (both instances), status and doctor (they compare dev with prod), and promote, seed-dev and refresh-dev (cross-env by nature). `benmore collaborators`, `benmore transfer-ownership`, `benmore transfers`, `benmore domain` (custom domains serve prod only), `benmore email`, `benmore email-domain`, `benmore sms`, `benmore payments`, `benmore dns`, `benmore github`, `benmore activity`, `benmore upload` and `benmore media` (one media library per app, shared by dev and prod) act on the app or the account: they accept `--env` and it changes nothing (`benmore media` and `benmore transfer-ownership` say so). `benmore tool <name>` passes `--env`, else the pin, to the tool as its `env` argument.
