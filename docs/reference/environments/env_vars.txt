Env vars are scoped per environment: SHARED (both), dev-only, or prod-only - UNIQUE per (app, scope, key). An instance loads shared overlaid with its own scope. A value set without a scope is SHARED and reaches both instances: MCP `set_env` with no `env`, and `benmore env <app> set` with no `--env` and no `benmore use` pin. To keep separate secrets (test key in dev, live key in prod) name the scope on every write: `env: "dev"` / `env: "prod"`, or `--env dev|prod`. Dashboard env tab has a scope selector + per-var scope badges; CLI `benmore env <app> set` writes the `--env` scope, else the pinned env's scope, else shared, and its confirmation names the scope it wrote (`scope: dev (the benmore use pin)`) with the flags that write the others. Platform-owned keys can't be set (and stored values are dropped): BENMORE_PLATFORM_*, BACKUP_S3_*, BENMORE_BIND_LOOPBACK, BENMORE_LISTEN, BENMORE_TRUST_PROXY, BENMORE_REQUIRE_ROUTER_SIG, BENMORE_AUDIT_WEBHOOK_ALLOW_HTTP, BENMORE_CLUSTER, the platform's socket and OAuth keys, the runtime metadata keys, and process-control keys (PATH, LD_*, DYLD_*, GIT_*, GODEBUG, and the Go runtime knobs GOMEMLIMIT, GOGC, GOMAXPROCS, GOTRACEBACK, plus the outbound proxy and TLS trust keys HTTP_PROXY, HTTPS_PROXY, NO_PROXY, ALL_PROXY (either case), REQUEST_METHOD, SSL_CERT_FILE, SSL_CERT_DIR and CREDENTIALS_DIRECTORY); ENCRYPTION_KEY is owner-only. `refresh-dev --with-data` copies prod's ENCRYPTION_KEY to dev so copied encrypted data decrypts. Scheduled backups are prod-only; destructive dev refresh explicitly preserves the prior dev database and matching key record. Durability knobs: `DB_SYNCHRONOUS=FULL` or `EXTRA` raises SQLite fsync safety for strict apps (default NORMAL); `BENMORE_WAL_SHIP=1` enables continuous prod WAL shipping to the BACKUP_S3 bucket with `benmore restore <app> --pitr --as-of <RFC3339>`. SQLite remains one writer plus many readers per app; `busy_timeout=10000` (10 s) absorbs short writer contention, but throughput is still bounded by commit latency.
