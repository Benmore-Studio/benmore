Dev and prod number the same migration the same way. A generated file names the schema it starts from and produces (`-- Schema-From:` / `-- Schema-To:`, digests of the parsed models). Before generating, an instance applies the pending generated files (copied by promote, refresh-dev or seed-dev, not yet in its ledger) whose headers lead from its last recorded schema to the loaded one, in name order and in one transaction, records each under its own name and writes nothing. If the files do not form that chain (for example files written by an older runtime), a statement fails, or the result differs from the schema, nothing is kept and it generates its own file. Hand-written migrations still run through the migration runner, once. Existing prod-only files are removed by the next promote's code mirror and reported as `instance_migration` by sync-status until then.
