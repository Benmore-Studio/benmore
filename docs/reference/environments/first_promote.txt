When prod has no database yet (the first promote, or a prod instance that never started), the dry run (MCP `promote` dry_run, `benmore promote --dry-run`, the dashboard publish preview) answers `first_promote: true` and the note `First promote: prod has no database yet. Promote creates it empty, creates every table in the schema and applies every migrations/ file; no data is copied from dev.` The answer of that first promote carries `first_promote: true` and a note that prod starts on a new, empty database: nothing was migrated and no pre-migrate backup was taken, because there was no data to back up. Later promotes migrate prod's data with a pre-migrate backup and say so.
