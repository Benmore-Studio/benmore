Every CODE overwrite (promote dev→prod, refresh-dev prod→dev) git-snapshots the DESTINATION first and auto-rolls-back the working tree if the copy fails - a partial/failed transfer never leaves an instance half-stomped, and the response hands back the restore command (`benmore git revert <app> <sha> --env <dev|prod>`). An all-files `refresh-dev` additionally REFUSES when it would overwrite/delete un-promoted dev code (the dev-first footgun: prod is usually behind dev, so the refresh would revert your work) - `--dry-run` previews the affected files, `--force` proceeds. (The copy compares content, sets no owner, mode or time on anything that already exists, and never follows or copies a symlink in either instance: symlinks and special files are skipped.)
