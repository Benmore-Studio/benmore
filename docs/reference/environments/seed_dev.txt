seed-dev / seed_dev give a prod-only app a dev instance: prod's code (no data, secrets, uploads or git history) is copied to <sub>-dev and committed as dev's own history, the dev instance is provisioned (first start creates an empty database) and the app is recorded as having one. It refuses while <sub>-dev exists (`destination already exists`) and is a no-op for an app that already has a dev instance. A seed_dev that fails after creating <sub>-dev undoes what it made, so it can be run again once the reported cause is fixed: the dev copy is stopped and removed, and the error ends `(the dev copy this call made was removed; seed_dev can be run again)`. Recording the dev instance is part of the call: a record write that fails is an error and undoes the seed. The undo never removes a database: when dev had started and created data.db, or cannot be stopped, the dev copy is kept and the error says `cleanup incomplete` and why; that case needs the platform operator.
