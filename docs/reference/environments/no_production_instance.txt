An app that has a dev instance has no production instance until its first `benmore promote <app>`, and none again after `benmore remove-production <app>` (its production data is kept and nothing runs on it). A command aimed at production then (`--env prod`, MCP `env: "prod"`, ?env=prod, or a `benmore use prod` pin) is refused with the code `no_production_instance`. MCP tools answer an error whose text starts `no_production_instance:`, says whether the app was never promoted or when production was removed, names `benmore promote <app>` as the next step and ends with the docs line. HTTP routes answer 409 `{error:'no_production_instance', message, hint, production:'none'|'removed', production_removed_at, docs}` (`production_removed_at` only for 'removed'), and the CLI prints the message and exits 1. This is the answer of the commands that read or change a running instance or its data: sql, users, health, check, describe, audit, requests, analytics, errors, feedback, testing-status, security-scan, restart, and `restore --from` / `--pitr`. A restart never brings a missing production back: only `benmore promote <app>` creates or publishes it (it needs a free live-app slot, see `publishing`). Until then target the dev instance with `--env dev` or no `--env`. Never promoted: `benmore logs`, `benmore tail`, `benmore restore` and `benmore integrity-check` with --env prod answer the same refusal, and `benmore open <app> --env prod` prints it instead of an address. Production removed: reads of what is kept still answer. `benmore logs <app> --env prod` prints the stopped instance's past log lines under a first line that says production was removed, `benmore integrity-check <app> --env prod` checks the kept database, and `benmore restore <app> --env prod` without --from lists the kept instance's backup files with `production:'removed'` and `production_removed_at` (restoring one is refused until the app is published again). The final backup `remove-production` took is named in its answer as `final_backup`, with `final_backup_note` saying where it is: on the hosted platform it is a stored snapshot (`<app>/pre-deploy-<UTC time>.db.gz`) that the dashboard's Backups view lists and downloads, not one of the instance's own backup files that `benmore restore` lists. Commands that do not need a running production are unaffected: `benmore env ... --env prod` (set production's values before the first promote), `benmore promote`, `benmore status`.
