Promotion requires a successful destination source snapshot before copying, including the first promotion into a new directory. A copied source whose commit fails is reported as saved with activation not attempted. Seeding refuses an existing dev directory and requires its initial history before provisioning; a seed that fails after creating the directory removes it again (`seed_dev`). Code refresh checks its final commit before activation. Failed copies can restore tracked source, but newly copied untracked files can remain; read the failure details. Git snapshots do not back up ignored files, databases or secrets. See api(at:"github") for history exclusions, failed-write receipts and contaminated-history handling.
