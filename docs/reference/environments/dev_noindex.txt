A hosted dev instance (<sub>-dev.benmore.ai) sends `X-Robots-Tag: noindex, nofollow` on every response (pages, static files, API answers), so search engines leave an unfinished build and its test data out of results and drop pages they already indexed; prod (<sub>.benmore.ai and custom domains) sends no such header. The generated /robots.txt on dev keeps `Allow: /` (a crawler blocked by Disallow could not read the noindex) and leaves out its Sitemap line. An app's own `static/robots.txt` is still served as written, and a flow or handler that sets its own X-Robots-Tag replaces the default. Nothing to configure: the instance is known from the platform-owned BENMORE_APP_NAME.
