Dev/prod environments (Model B). On a dev/prod-enabled host, a new app is born as its DEV instance at <sub>-dev.benmore.ai with its own data.db; the prod URL <sub>.benmore.ai stays vacant until you promote. write_file / edit_file / `benmore push` default to the dev instance. When the app is ready, `benmore promote <app>` copies CODE ONLY dev→prod (never data, secrets, or uploads), provisions prod lazily on first promote, migrates prod data with a pre-migrate backup, commits to prod's per-app git, and publishes at <sub>.benmore.ai. Iterate on dev, promote to ship.
