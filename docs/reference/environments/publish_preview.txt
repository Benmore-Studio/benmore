Dashboard POST /platform/app-promote?app=<sub>&dry_run=true returns code/schema changes and expected_dev_manifest for a sealed development source snapshot. Confirmation must send that hash; a changed source returns 409 before production writes and requires a fresh preview. Both dashboard publish controls preserve the preview's app identity. This fingerprints development source, not production state, and does not replace application testing or a live health check. Schema or database read failures block preview/promotion even with force. Missing/unreadable production data after restart or remaining schema differences return migration_verified:false; the dashboard shows verification pending. Source rollback restores code, not migrated data.
