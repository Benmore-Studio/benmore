`benmore env <app> list` prints where each value comes from: `KEY=…abcd (shared)`, `(prod)`, or `(prod, overrides shared)` for an instance value that hides a shared one, sorted by key. `--env dev|prod` lists that instance's effective set (default prod) and `--env shared` lists only the shared values. An unknown env is refused (400). `benmore env <app> unset KEY --env <scope>` removes KEY from that scope only; when KEY has no value there nothing is removed and the CLI exits 5 with `Error 404: KEY is not set in the shared scope (set in: prod). Nothing was removed.` An unset of several keys is all or nothing. After the `✓ KEY removed` lines the CLI prints on stderr which scope it removed from and what is left, as `set` does for the scope it wrote: `scope: dev (the benmore use pin): removed from the dev instance only. A shared value, if one is set, is what dev reads now; ...`; with no `--env` and no pin the scope is shared, and a value set for one instance stays. MCP `list_env` takes env=shared and adds `scopes` (key → shared, dev or prod) and `overrides_shared`; `unset_env` answers the same error. GET /platform/env returns the scoped form `{environment, vars:[{key, value, scope, overrides_shared}]}` with `?scopes=1`; without it the answer is the KEY→masked map.
