Hooks (and `on: event` data-event flows, which follow the same rule) fire only for these writes: auto-CRUD (POST/PATCH/DELETE /api/<table>, restore, batch create/update/delete and /api/_transaction; NDJSON /ingest runs the table's before_insert hooks on each row but fires no on_insert hooks, event flows or webhook deliveries; bulk import does not), workflow transitions, POST /api/_groups/create (tenant bootstrap) and approved MCP command applies; `_benmore_users` hooks fire from the auth endpoints (insert on sign-up, update on sign-in and account changes). Every other write fires nothing: a flow's `run: sql` / `sql_dynamic` (whatever started the flow: request, cron, async job, data event, on_error handler), a cron.yaml `sql:` job, a hook's own `sql:`, and operator SQL. Flow and cron writes still send live table events (api({at:'flows'}) → realtime_events). To notify, email or call out from a flow or cron job, do it in the flow: `run: notify` (api({at:'flows'}) → notify_step), `run: email`, `run: webhook`.
