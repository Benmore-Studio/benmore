`when:` on a hooks.yaml entry, a workflows.yaml transition or an on_transition entry is a SQLite condition over the event row: `when: "status = 'paid' AND old_status != 'paid'"`, `status IN ('approved','denied')`, `assignee_id IS NOT NULL`, `hold_until <= datetime('now') AND NOT EXISTS (SELECT 1 FROM exceptions x WHERE x.booking_id = bookings.id)`. The row is a one-row table named after the hook's table with every column, `old_<column>` (the previous value on updates, NULL otherwise), the caller's user_id, user_email, user_role, user_roles and user_group_id (NULL without a session), `_submitted` on before-hooks, and the other submitted fields. Name columns directly; `<table>.<column>` is the event row and `main.<table>` the stored table. Values are bound, never pasted into the SQL, and carry their column's declared type as in a query on the table: numeric text in an Int column compares as a number, a String column compares as text (`'10' > '9'` is false there). The condition is one read-only expression (it may read other tables; no `;`, and no `?`/`:name` parameters) and is stopped after 2 seconds. NULLs follow SQL with one exception: outside subqueries `!=`/`<>` is NULL-safe (`IS NOT`), so `status != 'paid'` holds for a NULL status and `old_x != x` holds when x is first set or cleared, while next to the empty string NULL counts as empty, so `phone != ''` means "has a value". Other comparisons with NULL are false: `x = ''` is false for NULL (write `coalesce(x, '') = ''`) and so are `x < 5` / `x <= 5`. Quote text: an unquoted word is a column (`status = paid` fails). A `when:` is not a template: `{{status}} = 'paid'` is refused at write time and never matches. A condition that can't be evaluated (a template, an unknown column, a syntax error, the time limit) fails closed and is logged once: a before-hook refuses the write (422, as for hook SQL that fails), an after-hook or on_transition hook doesn't fire, a transition answers 422 `condition not met`. For a transition the row is the stored row before the change, without session keys filled in, so user_id is the row's own column when the table has one. The write gate and `benmore check` prepare every `when:` against schema.prisma (old_* and the session keys included) and refuse one that can't be evaluated, naming the entry (`on_update.orders[0]`, `orders.transitions.pending -> shipped`); an existing file still loads, with a warning in the app log.
