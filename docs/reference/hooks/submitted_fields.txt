Before-hooks (before_insert/before_update, CRUD, batch, NDJSON /ingest and /api/_transaction) get {{_submitted}}: the columns the request is writing, as ",a,b," - known, non-protected columns it sent a value for. Keys the write drops (_csrf, query parameters, unknown or protected names) and the user_id / tenant key the framework fills in are not listed. Test a field with instr('{{_submitted}}', ',weight,') > 0 - e.g. to allow a client to change status and nothing else. An unsubmitted {{field}} renders as its own literal text, but a caller can send that text as a value, so don't rely on comparing against the placeholder. On an update, hook SQL placeholders are the request's values only (id, the submitted columns, {{_submitted}} and the session keys): `'{{status}}' = 'approved'` asks whether this request sets status, and a stored value is read with a subquery (`(SELECT status FROM orders WHERE id = {{id}})`). `when:` is different: it is judged over the row as it will be, stored columns included. A workflow transition submits no fields, so its hook SQL sees the whole row with the target state.
