Hook SQL announces the tables it writes, as a queued job and inside an update's transaction alike, also when the statement starts with a comment or quotes the table name. This includes the SQL an app.yaml `auto_memberships:` block generates. Each written table is announced as `{table, action:'refresh'}` with the audience a flow write gets: a hook job (insert and delete hooks, and any hook with a non-SQL action) takes it from the triggering row, its tenant key for a tenant-keyed table (readers in that tenant get the table name; a row with no tenant key reaches admins only) and its user_id (the writer, or the stored owner of a sessionless write) for an owner table; a SQL-only update hook, which runs in the update's transaction, takes it from the writing session like the update's own event. Delivery still applies the SSE/WebSocket read and credential gates, and member/owner-scoped readers other than that user receive the tableless hint and refetch through the guarded API. No row contents are published.
