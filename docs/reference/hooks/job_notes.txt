A queued hook whose action was skipped or failed (a `notify:` to a user id with no account, an `sms:` whose recipient resolved empty, an email or webhook that was not delivered, hook SQL that failed) completes with the reason in the job's `error` column, so `GET /api/_jobs` and describe_jobs show `status: completed` plus why. Nothing is retried (a retry could send twice). Hooks queued by an approved connector command fail the job instead.
