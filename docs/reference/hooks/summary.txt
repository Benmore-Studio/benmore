After-CRUD side effects defined in hooks.yaml. Insert and delete hooks, and an update hook with any non-SQL action (webhook, email, notify, ws, sms), run as queued jobs after the write: they do not block the response and a failed action is recorded on the job. An on_update entry that is only `sql:` runs inside the update's transaction: if its SQL fails the update is rolled back and the request answers 500 `update side effect failed`. Before-hooks run first and can refuse the write with 422.
