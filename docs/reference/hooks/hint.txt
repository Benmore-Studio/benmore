Session context in hooks: {{user_email}}, {{user_id}}, {{user_role}}, {{user_roles}}, {{user_group_id}}. For a signed-in caller these come from the session and override any same-named request field; {{user_group_id}} is the caller's current tenant (an admin's act-as tenant) and is absent when the caller has none. before_update and on_update hooks see {{old_<col>}} for every column: the value stored before the change, in `when:` and in the hook's placeholders, on every update (PATCH, batch, /api/_transaction, restore, a version revert, a workflow transition and an approved MCP command). `when: "old_status = 'done' AND status != 'done'"` on a before_update hook refuses reopening a done row. A column of the table that is itself named old_<x> keeps its own value in a before_update hook and is not the previous <x>.
