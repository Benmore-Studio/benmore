A retention policy (retention.yaml) that deletes a row of a versioned table deletes that row's stored versions with it, in one transaction: once the sweep has deleted a row, <table>_history, /versions and ?as_of= do not return it. This covers the rows the policy deletes by its column and the soft-deleted rows it purges; the sweep's audit entry counts them (api({at:'retention'}) effects). Versions of rows that stay are kept, including an expired row that is kept because another table's row still references it. The stored versions of a row that was deleted some other way (through the API) age out by the same policy: each is deleted once the policy's column, as that version holds it, is older than the ttl.
