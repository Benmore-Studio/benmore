Newly generated history chains the latest retained boundaries and source timestamps. A canonical update closes its prior version at the precise advancing updated_at; raw writes and deletes use a nanosecond clock boundary that advances beyond the prior start. SQLite whole-second CURRENT_TIMESTAMP does not close a fractional interval before it begins. Existing history bytes and version IDs are retained: unknown, pruned or inverted old intervals are not repaired by inventing timestamps. When no stored interval matches, the current row is returned only at or after its latest known source/history boundary; older gaps answer not found. Prisma @updatedAt maintenance preserves explicitly changed timestamps and never regresses fractional/future values during encryption or blind-index updates. Its implicit raw-SQL maintenance remains whole-second; authored SQL still owns its concurrency contract. Known legacy generated timestamp triggers upgrade atomically; an altered same-named trigger is refused rather than overwritten.
