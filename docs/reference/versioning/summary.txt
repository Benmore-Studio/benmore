Every update and delete snapshots the row it replaces (an insert records no version). List versions, revert to a specific version, or query the table as-of a timestamp. The endpoints serve history only while the row is readable: after a delete, /versions, /versions/<v>, /revert/<v> and ?as_of= answer 404 for everyone, admins included. A soft-deleted row (a table with deleted_at; its delete is recorded as an `update` version) is reachable again after POST /api/<table>/<id>/restore. A hard-deleted row's snapshots, including the `delete` one, stay in `<table>_history` and can be read only with SQL.
