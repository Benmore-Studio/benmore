A revert never restores a hidden credential column (the names api(at:'scoping') → hidden_columns strips from every response: `*_token`, `*_secret`, `*_password`, `api_key`, ...). It keeps its current value and `kept` lists it with reason `hidden`. Version snapshots omit these columns, so the reverting caller cannot see what the version holds; restoring it would let anyone who may edit the row bring back a token or secret that was rotated or revoked. App admins get the same result: they cannot read hidden columns either. To set an old value on purpose, PATCH the column with it. An encrypted column with unmask_roles is not hidden and reverts like any other column.
