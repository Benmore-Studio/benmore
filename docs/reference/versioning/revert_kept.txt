A revert restores only what the version holds; every other column keeps its current value, and the answer lists them: `kept: [{column, reason}]`, reason `command_owned`, `workflow_state`, `protected` (ownership, tenant, identity, computed and blind-index columns; created_at and deleted_at), `hidden` (a hidden credential column, see revert_hidden) or `not_in_version`. A version records no column set, so `not_in_version` means a column the history table lacks, or a NULL in the version for a column the table now declares NOT NULL (history adds a new column with NULL for every older version). A nullable column added after the version cannot be told apart from one that was empty and takes the version's NULL. `owned_fields_kept` still lists the command-owned columns. id is never written; updated_at takes the revert's own write time.
