/api/_query refuses encrypted-column SUM/AVG/MIN/MAX, grouping, sorting and value filters with 400, including for callers allowed to unmask. SQLite would otherwise operate on randomized ciphertext and silently return false zero totals, empty equality matches or arbitrary ordering. Plain projections still decrypt and mask by current access. COUNT(*) and permission-authorized COUNT(column), IS NULL and IS NOT NULL remain supported. Equality lookup through a configured blind index uses native CRUD filters instead; use a non-sensitive derived column for database reports/ranges. Custom SQL flows own their SQL semantics and authorization.
