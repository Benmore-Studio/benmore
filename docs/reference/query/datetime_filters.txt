A where value on a DateTime column (declared DATETIME, DATE or TIMESTAMP) that is an ISO-8601 date or date-time string is compared as an instant, as a plain value and with eq, ne, gt, gte, lt, lte and in (when every item of the list is one), and order_by on such a column orders by instant (created_at and updated_at keep the plain, index-served ORDER BY: no request can write them and the spellings the framework writes already order as text): `{created_at: {gte: '2026-01-15T00:00:00Z'}}` finds a row stored as `2026-01-15 10:00:00`, and a row written with an offset matches and sorts by its instant. like, contains, starts_with and ends_with still match the stored text, and so does a value that is no date. A stored value SQLite cannot read as a date is compared as text and sorts before every date when ascending. group_by, min and max on a DateTime column still work on the stored text. Report `sources:` where values and order_by follow the same rule. Cost and details: api({at:'scoping'}) datetime_filters.
