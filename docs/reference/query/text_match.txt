`like` is a substring match: the value is wrapped in %...% (`{like:'acme'}` is LIKE '%acme%'), and a % or _ in the value stays a wildcard (`{like:'a_c'}` also matches 'abc'). `contains`, `starts_with` and `ends_with` match the value as literal text (% and _ and \ in it match only themselves): `{name:{starts_with:'INV-'}}`, `{file:{ends_with:'.pdf'}}`, `{code:{contains:'a_b'}}`. Their value must be a string (400 otherwise). All four compare ASCII letters case-insensitively ('acme' matches 'ACME') and other letters exactly ('é' does not match 'É'), as SQLite's LIKE does. Like every value filter they are refused on an encrypted column (400).
