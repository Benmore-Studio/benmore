A job's payload holds the full written row and env-derived enqueue values for delivery, so reads redact it: admin `GET /api/_jobs/{id}` and describe_jobs replace values of hidden-column names, encrypted-field columns, `_blind` siblings and env-derived enqueue keys with "[redacted]", and query_db / the console read `_benmore_jobs.payload` as NULL. Hooks, webhooks and flows still receive the whole payload. In hook and webhook-subscription jobs the row's encrypted.yaml columns and their `old_` deltas are stored sealed under the app's ENCRYPTION_KEY and opened at delivery, so the receiver gets the same body; key rotation re-seals pending, running and failed jobs. Event-flow and async-flow payloads are not sealed.
