An aggregate takes only `fn`, `col` and `as`. Any other key answers 400 naming it and the accepted keys (`unknown aggregate key "field": accepted keys are fn, col, as`), followed by the corrected aggregate when the column was written under `field:` (`; aggregates take "col": {fn:'sum', col:'qty'}`). Use `col`: `{fn:'count', field:'status'}` is refused, not run as COUNT(*). Applies to POST /api/_query; a saved view's spec is checked when a client runs it.
