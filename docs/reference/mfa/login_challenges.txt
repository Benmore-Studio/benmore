Login-time MFA challenges are one-use and bound to the current credential generation, including when continuing to auth.otp. Password changes/resets, MFA activation/disable and account access revocation invalidate pending steps. Challenge consumption, successful TOTP/backup-code consumption and session creation commit together (also for inline password+MFA); replay with another valid factor creates no second session. See api(at:"auth") signin_steps for expiry and upgrade behavior.
