The app serves the pages a sign-in is sent to; the framework serves only their POST handlers. After a correct password, /login sends an MFA-enrolled account to /verify-mfa and a role listed in auth.require_mfa_for_roles to auth.mfa_setup_redirect (default /mfa-setup). A form post gets a 303 there; a JSON request (Accept or Content-Type application/json, as bm.auth.signIn sends) gets 200 {ok: true, mfa_required: true, redirect} or {ok: true, mfa_setup_required: true, redirect} with the step cookie set and no session. Both carry a same-origin ?next= from the login request. POST /signup answers the same way for a new account whose role is listed (`*` lists every account): the setup cookie, 200 {ok: true, mfa_setup_required: true, redirect} or a 303 to the setup page, and no session; bm.auth.signUp sends the browser there. The decision is made for the account as created: a role an on_insert hook assigns afterwards (hooks are queued) is not seen, so that account gets a session and is held from its next request. With auth.otp the emailed code still comes first and the OTP step starts enrollment; with auth.require_verified sign-up still answers email_verification_required. The /verify-mfa page is a form that POSTs mfa_code (or code: a 6-digit TOTP or a backup code) and next to /verify-mfa; a form post gets a 303 to next (else auth.redirect, else /) or back to /verify-mfa?error=..., a JSON post {ok: true, user} or {ok: false, error}. The /mfa-setup page calls bm.mfa.enroll() and bm.mfa.verify(code), which signs the person in; for a person who arrives holding a session instead of the setup cookie, enroll() answers 400 and the page asks for the current password, calls bm.mfa.enroll(password) and offers sign-out (existing_credentials). New HTML scaffolds ship both pages (static/verify-mfa.html, static/mfa-setup.html, wired by lib/auth.ts initAuthPage); an app without them serves its SPA index.html at those paths, signed out, so an MFA account cannot finish signing in until the app adds them: copy them (and lib/auth.ts initAuthPage/initMFASetup) from a new scaffold. See api(at:"auth") step_pages.
