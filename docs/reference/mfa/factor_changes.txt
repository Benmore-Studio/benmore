Setup and verify require a login session or the purpose-bound first-enrollment setup token. From a login session, setup also requires the current password in the JSON body ({password} or {current_password}; 400 when missing, 403 when wrong, shared 5-try lockout with other signed-in password proofs); the login-issued setup token needs none because it already follows a password login. Accounts that only sign in through OAuth have no usable password and cannot enroll from a session. API tokens and support/act-as sessions cannot manage MFA. Setup refuses to replace an active factor: disable it with a current TOTP code first, then enroll the replacement. Concurrent setup/verification changes fail with 409 instead of overwriting a factor.
