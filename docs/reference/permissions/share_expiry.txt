Optional expires_at on POST /api/<table>/<id>/share and bm.permissions.share must be understood by the same SQLite datetime parser used when enforcing record grants. Supported RFC3339 timestamps (including offsets), SQLite date/time strings and valid past dates remain accepted; empty or omitted means no expiry. A malformed or unsupported nonempty value returns 400 before upsert or audit, preserving any existing grant. Accepted values retain their original stored representation. A grant whose stored expires_at is malformed stays inert; explicit revoke remains available. This is not the separate global/tenant role-grant RFC3339/future-only policy. Scope, CSRF and current sharing authority still run first.
