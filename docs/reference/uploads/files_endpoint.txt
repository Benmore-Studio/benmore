POST /api/_files is the upload route without a folder choice: a multipart body with one file part named `file` (plus `_csrf` for a cookie session; sign-in is required when the app uses auth). It answers `{url, name, size, type}`: `url` is the stored reference, `name` the original filename, `size` the bytes received and `type` the content type the client declared for the part (it is reported, not checked). The file is stored PUBLIC under `uploads/_files/` (private, under `uploads/private/_files/`, only with `compliance: hipaa`); there is no `kind`, so for a private file use POST /api/_upload with `kind=private`, which is also the route `bm.upload` calls. A scoped API token or scoped Bearer session uploads here, and on POST /api/_upload, only with a `table` field (multipart field or query parameter) naming an app table whose write scope it holds, else 403 `scope denied: ...` (api(at:"auth.scoped_credential_routes")). Size caps, refused types (415), the media allowance (507) and the `features.uploads` switch apply as on POST /api/_upload. Like every public upload, the app can delete the file only with `run: delete_upload` and `record:` (public_deletion), and cached copies outlive the delete (public_vs_private).
