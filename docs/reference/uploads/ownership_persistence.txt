Private HTTP uploads and MCP file pulls must persist uploader ownership before saving bytes. A database/schema failure fails the operation without writing the file. A storage failure retains the ownership reservation because remote bytes may already exist. Generated destinations cannot replace another uploader's ownership; matching MCP retries reuse their reservation. Existing legacy files retain the documented reference-only signing rule. A public upload's uploader record (public_deletion) is best effort: when it cannot be written the upload still succeeds, the app log notes it, and the file falls under the reference-only rule if the app later deletes it.
