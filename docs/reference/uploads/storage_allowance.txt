On the hosted platform every account has a media storage allowance from the owner's plan: free: 1 GB; Pro ($39/month): 10 GB; Scale ($149/month): 100 GB; the operator's own staff and admin plans have no limit. It is per ACCOUNT, not per app: it sums the files stored by every app the owner owns, dev and prod instances together (POST /api/_upload, POST /api/_files, multipart creates, and the files that flow steps and connector commands store), plus those apps' dashboard media libraries. An upload that would take the account past its allowance is refused before anything is stored. POST /api/_upload, POST /api/_files and a multipart POST /api/<table> answer 507 `{"error":"storage cap reached","code":"media_storage_limit","docs":"uploads.storage_allowance","used_bytes":<bytes the account stores>,"limit_bytes":<its allowance>,"detail":"<the usage, the allowance and the way out>"}`, and the create stores no row. The database limit answers the same status and `error` with code `storage_limit` (api(at:"recovery") `storage_limit`), so branch on `code`. A flow step or connector command that stores a file fails with the same `detail` text. Only NEW uploads are refused. Reading, serving, signing and deleting files always works, nothing is deleted automatically, and an account over its allowance keeps every file. The way out is to delete files (`run: delete_upload`, the dashboard media library, deleting an app) or to upgrade the owner's plan. A deleted file's size is free again at once; a file deleted within two minutes of its own upload is freed after those two minutes. The count follows what storage holds: an upload that failed half way, or one that replaced a file, can count for up to an hour before it is corrected. GET /platform/billing/me reports `media_bytes_used` and `media_bytes_limit` in bytes (`media_bytes_limit` is null and `media_unlimited` true when there is no limit), and the dashboard's /upgrade page shows them. Dashboard media library uploads (`benmore upload`, the dashboard, MCP upload_media and request_upload_url) are refused the same way: 507 with the same body over HTTP, the `detail` text from the MCP tools. An app that stores uploads in its own bucket (S3_BUCKET) or runs self-hosted has no allowance.
