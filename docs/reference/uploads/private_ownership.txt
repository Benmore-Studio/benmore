A private upload records who uploaded it. bm.signedUrl(path, {record}) signs only when that record vouches for the uploader: the caller uploaded it, the record's user_id is the uploader, the record is in the uploader's tenant, or an admin uploaded it. So a path copied into someone else's record can't be signed. Files with no ownership row (uploaded by an older runtime) keep the reference-only check. `run: serve_file` (for a private file) and `run: delete_upload` take `with.record` naming the row that owns the file: `with: { path: '${{ steps.doc.outputs.file_url }}', record: { table: documents, id: '${{ steps.doc.outputs.id }}' } }`. With it they apply the same rule before reading, redirecting or deleting anything: the row must reference the file and belong to the uploader (`user_id`) or the uploader's tenant (an admin upload or a file with no ownership row still passes); `table` is a literal name. So a reference another user copied into their own row is refused: 403 from serve_file, a failed flow from delete_upload. Without `record:` the rule is advisory: the flow's SQL is the only gate, and the app log notes a private file the caller did not upload. Add `record:` to every serve_file and delete_upload of user uploads (the owner-scoped lookup row, a teammate's file in a shared tenant, an anonymous share link, a cron or event flow). `benmore check` warns about either step without `record:` in a flow with no signed-in caller (public, scheduled or event).
