Set app.yaml `features.uploads: false` to turn file uploads off on every path (default: on; `no` and `off` are read as false). POST /api/_upload and POST /api/_files answer 404 before the body is parsed. A multipart POST /api/<table> that carries a file part answers 403 `{"error":"uploads_disabled","field":"<the file part's name>","message":"file uploads are turned off for this app (features.uploads: false in app.yaml): the file was not accepted and nothing was saved; send the request without file parts"}` before anything is stored: no file, no ownership record, no table row and no audit entry. A multipart create with fields only is an ordinary create, and so are JSON and form creates. Updates, batch, ingest and /api/_transaction never store a file (a file column is an ordinary text column to them), so they behave the same with the switch on or off. A connector command that pulls a file from a connection answers `denied` when it is prepared, and a pull approved earlier fails without downloading. The switch covers files that clients and connector sources send; files already stored stay readable, operator imports are unaffected, and files the app produces itself (stamped PDFs, connector exports, image transforms) are not uploads.
