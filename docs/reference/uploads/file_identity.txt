Local upload downloads, serve_file, direct static downloads, HTML/service-worker reads, private connector file reads and image transforms use a validated open file handle for their bytes and MIME inspection. Replacing a pathname or parent with an alias after validation cannot redirect the read into another file. Existing in-root aliases and symlink-mounted upload roots remain supported. Each caller retains its existing authorization and namespace checks; direct upload serving checks the pinned resolved namespace. This pins file identity, not an immutable snapshot of in-place writes; TSX dependency compilation uses its separate containment boundary.
