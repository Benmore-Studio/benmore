Local upload downloads, serve_file, direct static downloads, HTML/service-worker reads, private connector file reads and image transforms use a validated open file handle for their bytes and MIME inspection. Replacing a pathname or parent with an alias after validation cannot redirect the read into another file. Existing in-root aliases and symlink-mounted upload roots remain supported. Each caller retains its existing authorization and namespace checks; direct upload serving checks the pinned resolved namespace. This pins file identity, not an immutable snapshot of in-place writes; TSX dependency compilation uses its separate containment boundary. A local upload is reached only by the exact name it is stored under: every part of a reference below uploads/ is compared byte for byte with the stored folder and file names, with no lower-casing and no Unicode normalization. On a disk that ignores letter case or normalization (the macOS and Windows defaults) another spelling of a stored name (`uploads/private/<id>.PDF` for a stored `.pdf`, `uploads/PRIVATE/<id>.pdf`) therefore names no file, as it does on Linux and in object storage: serve_file, GET /uploads/... and a signed link answer 404, GET /api/_signed_url answers 400 `use the canonical upload path`, connector file reads, flow steps that read a private file and image transforms find no file, and delete_upload fails and deletes nothing. Store and pass a reference exactly as the upload returned it. On such a disk, write each upload folder under one spelling: a second letter case of an existing folder (`Avatars` after `avatars`) stores its files in the existing folder, and the references returned for them do not resolve.
