`bm.upload(file, opts)` sends one File or Blob to POST /api/_upload (with the page's CSRF token) and resolves `{path, url, filename, size}`: `path` and `url` are the same stored reference (store it in a column and render or sign it exactly as returned), `filename` is the name that was sent and `size` the bytes received. `opts.kind` is the storage folder: leave it out for a PUBLIC file (folder `files`), pass `kind: 'private'` for a PRIVATE one, read later with `bm.signedUrl(path, { record: { table, id } })` or a `run: serve_file` flow; any other name is a public folder (see summary and public_vs_private). `opts.filename` is the name to send instead of the File's own; a Blob has no name and is sent as `upload`, so give it one with an extension (`bm.upload(blob, { filename: 'scan.pdf' })`): the extension becomes the stored file's and decides its served content type, and the hosted platform refuses a name with none (415, see size_limits). A private upload from page code: `const { path } = await bm.upload(file, { kind: 'private' }); await bm.table('documents').create({ name: file.name, file_url: path });`. A refused upload throws the Error every bm call throws (`err.status`, `err.code`, `err.message`, `err.body`): 415 for a refused type, 413 over the size cap, 507 with `err.body.code` `media_storage_limit` over the account's media allowance, and 404 with `err.code` `uploads_disabled` when the app has uploads switched off (feature_gate).
